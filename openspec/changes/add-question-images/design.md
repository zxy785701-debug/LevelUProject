# Design

## Context

普通主题及材料关卡由 quiz_grounding.process_generation 审核后调用 Accounts.store_quiz。知识库使用独立 Worker、租约、检查点及事务发布。题库与学习轮次均存 JSON 快照，公开 DTO 与持久化 DTO 分离。当前工作区保留大量既有未提交改动。

## Goals / Non-Goals

Goals: 不改出题和奖励规则；可选能力独立初始化；单题失败隔离；数据库保证跨进程额度与恢复幂等；两条发布链共用配图服务。

Non-Goals: 不扩展图像编辑、选项配图、语音或支付；不升级已有核心框架；不把图片当事实核实依据。

## Decisions

1. 新增 question_images 模块，httpx 调用百炼原生同步接口，每题 n=1、size=512*512；最多五题受控并发。一次 n=5 只能变体同一 Prompt，不能准确匹配五题，因此不用该方式。
2. 独立配置惰性加载，优先独立生图 key/endpoint，未填写时复用现有 KNOWLEDGE_EMBEDDING_API_KEY/BASE_URL；不依赖知识库 enabled。COS 凭据及 HTTPS 分发域名只在后端。缺配置时整个配图阶段降级，未启用时零外部调用。
3. 新增独立日用量表和逐题调用记录。身份摘要与上海日期控制计数，唯一操作/题目键控制恢复。开始调用前短事务记账，不在网络等待期间持锁；响应丢失的调用保守计数且不自动重发。成功 URL、对象键持久保存，恢复可以复用。跨日使用调用记录原日期，不把旧调用移到新日。
4. AI 草稿 schema 继续只接收原有题目。仅持久化题目及公开 DTO 增加 image_url，Quiz 增加配图结果摘要。客户端不能提供 URL 参与判分或伪造已生成图片。未启用配图的请求摘要排除默认 false，保持旧幂等恢复键有效。
5. 审核通过后进入 generating_images，留出数据库发布时间。图片阶段有独立预算，并受剩余总时间约束，超时后发布文字。知识库先保存 validated-quiz 再配图，沿用原逻辑操作 ID；成功与失败调用记录阻止恢复重复调用，发布仍验证租约和文档权限。
6. 下载只接受可信百炼结果 HTTPS 主机及公开地址，不把百炼认证头转发下载站；限制响应字节并用 Pillow 校验 PNG/JPEG/WebP，上传统一 PNG。COS 同步 SDK 在线程执行，有限连接/读取超时与重试；对象键随机命名，不含题目正文或账号标识。保存公开 HTTPS 分发 URL，不保存签名临时 URL。
7. 前端共用开关与配图展示组件，显示额度及部分失败提示；图片预留正方形空间、限制手机高度，加载失败提示不阻断题目。持久恢复请求保留当时开关。私有资料配图开关说明题目描述会发往百炼、配图通过公开地址分发。

## Risks / Trade-offs

- 网络响应丢失后无法证明服务商是否出图：记录已开始且不自动重新扣费；文字关卡继续发布。
- 生图晚于文字审核：独立阶段与剩余预算，保留发布余量；旧关闭配图操作不改变期限。
- COS 新桶默认域名浏览器预览限制：使用 COS_PUBLIC_BASE_URL 配置 HTTPS 自定义域名/CDN；用户已同意配置后再做真实验收。
- 公开图片 URL 可被持有者访问：仅用于用户主动启用的 AI 配图，不上传原始文档；界面明确说明。

## Migration Plan

新增 008_question_images 增量表，不改旧 JSON。安装新增锁定 COS SDK 后执行原启动迁移。可通过关闭配图能力回退新调用，历史图片与题目快照继续保留。测试只重置独立 levelup_test 数据库，不并行运行两个后端测试进程。

## Open Questions

COS 存储桶、地域、访问域名和凭据由用户在真实联调前配置；此项不阻碍已批准的开发和受控自动测试。

## 2026-10-24 已批准的画面描述优化

真实模型把带题干的提示词画成文字海报。用户批准复用现有文字模型，通常每轮增加一次批量调用，将题干/知识点转换为英文纯画面描述；不传选项、答案或解析。生图仅接收画面描述与简短构图约束。

新增 009_image_plans 增量迁移保存按用户/操作唯一的描述计划、输入摘要及状态。已保存计划恢复时复用；已开始但响应未知的描述请求不自动重发。文字模型沿用原调用计数、速率与总预算；图片阶段总时限包含描述步骤。额度为零、能力不可用、操作取消时不调用描述模型。描述失败只返回文字，不回退为带题干的生图提示词。原生图逐题请求、额度、并发与 COS 流程保持有效。

真实同时发起五次出现两次成功、三次 429。官方当前北京 qwen-image-2.0 限流为每秒两次。用户批准错开发出并保持最多五个在途请求：010_image_dispatch 新表用短 MySQL 行锁预订未来发送时间，API/Worker 默认间隔 0.55 秒。连接初始化完成后才排队，错过发送时刻的名额重新预订，避免 SQL 返回结果因事件循环阻塞而扎堆发出；等待不持事务，仍受阶段期限/取消检查控制。已预留但未发出的请求取消或失败时释放预留额度，响应未知的已发出请求不重试。
