# Design

## Context

动机见 [proposal.md](proposal.md)。本方案基于当前源码与 `docs/需求分析文档.md`、`docs/方案设计文档.md`、`docs/多源输入与个人分析开发方案.md`、现有 OpenSpec、用户提供的架构图及本次人工确认。早期文档中的无账号、前端判分、Jina 等描述已经落后于实现，以当前代码和后续人工决定为准。

### 已有能力与扩展位置

| 现状（已检查源码） | 对本方案的约束 |
| --- | --- |
| FastAPI、MySQL、Python 3.13；LangChain 1.x、DeepSeek、官方 Tavily 双工具已经在用 | 新增领域模块，不重做账号、模型网关和联网服务 |
| `backend/app/materials/` 已有文字 PDF、DOCX、TXT 解析、公开网址校验、网页提取、材料预览 | 复用解析与安全校验；补 Markdown，不整体替换解析器 |
| 现有材料与任务有临时清理策略；后台执行依靠进程内任务 | 私有知识库另建长期数据与持久任务，不能直接复用临时材料生命周期 |
| `backend/app/quiz_grounding/` 已有 Agent、证据登记、范围快照、独立审核与实际模型调用计数 | 复用约束和审核，新建能在无 Tavily 时继续查知识库的检索入口 |
| 旧证据主要面向网页；材料上下文通常是一份材料；来源结构严格校验 | 显式增加多文档引用字段与适配，不能把任意 JSON 塞入旧结构 |
| 服务端掌握判分、额度、奖励、错题、报告；最终发布有关联数据库事务 | 知识库出题必须进入同一发布与作答链路，不能另造一套判分 |
| Taro 前端现有“私有知识库”入口尚未实现；已有多主题确认、来源阅读、后台任务轮询 | 新增知识库页面和任务状态，复用已有交互；保持旧入口及存储键隔离 |

现有每账号每分钟 10 次实际模型调用、单账号 AI 操作并发限制、主题多选、确认本题后揭晓答案、末题自动报告、学习记录删除等行为均为回归边界。

## Goals / Non-Goals

**Goals:** 在现有系统旁增加独立、可关闭的知识库领域；MySQL 为事实与权限来源，Chroma 为可重建索引；所有耗时步骤脱离小程序单次请求；私有资料与公网资料有可验证的出处和权限；按 TDD 实施后再启用。

**Non-Goals:** 本期不做共享知识库、文件夹树、OCR、旧版 `.doc`、视频入库、网站整站爬取、自动定时更新、多轮聊天记忆和分布式高可用。旧资料不会自动转存；现有视频、文档、网页和主题直接出题流程继续存在。用户所谓“离线建库”在此表示预先异步建索引，云端 Embedding 仍需要联网。

已确认的产品决定：同时提供问答和出题；用户主动添加资料至“我的知识库”；**新知识库流程默认允许 Agent 联网补充，可手动关闭**。这不改变旧材料直接出题默认不联网的规则。

## Decisions

### 1. 使用增量领域模块，保持旧入口兼容

新增 `backend/app/knowledge/`，负责资料、分块、Embedding、索引、任务、检索、问答及知识库出题编排；新增路由统一放在 `/api/v1/knowledge/`。共享部分只增加可选来源字段、受控发布适配和账号删除清理钩子，保留旧字段默认值与旧接口响应。

选择此方式是因为直接把现有 `Material` 改为长期知识库，会改变 24 小时清理、单材料准备及旧历史语义。社区 Loader 可作为后续新增格式的适配器，不为使用框架而替换已经验证的解析器。

### 2. 数据分层与版本发布

| 持久数据 | 职责 |
| --- | --- |
| `knowledge_documents` | 账号归属、名称、来源类型、文件摘要/网址、生命周期、活动版本、删除标记 |
| `knowledge_revisions`、`knowledge_chunks` | 规范化原文、分块、页码/标题/位置、内容哈希、索引配置、活动/暂存版本 |
| `knowledge_jobs`、阶段检查点 | 任务类型、幂等键、状态、单调进度、租约、截止时间、预算、结果关联与错误码 |
| `knowledge_scopes` | 原始学习目标、选中文档及版本、主题候选、联网权限与证据快照 |
| `knowledge_questions` | 单次问答请求、回答、引用快照、来源状态与删除标记 |
| 账号清理 outbox | 不依赖已删除用户外键的持久清理指令，记录待删索引与文件位置 |
| Chroma | 每用户、每 Embedding 配置的向量索引；可以由原文和分块重建 |
| 私有文件目录 | 服务器生成路径的原始文件；不直接暴露公开下载地址 |

不把 Chroma 作为权限、任务状态和唯一正文存储。集合名由服务端账号内部 ID 与配置摘要生成，客户端不能指定集合、路径、用户 ID 或过滤表达式。每次检索还须按 MySQL 当前归属、未删除、已就绪文档和活动版本复核结果。

索引单位为文档版本。分块 ID 由文档、版本、内容位置确定，同一重试使用幂等 upsert；只有所有分块、向量数量、维度及索引清单校验通过，才在 MySQL 事务中切换活动版本。重建失败保留旧活动版本；半成品从不参与检索。模型、维度或距离度量变化建立新配置集合，完整重建后切换，不能混合使用。

删除先在事务中标记不可用并写清理任务，随后的检索、范围确认和新出题立即排除该资料；后台删除向量与文件，失败可重试。删除资料不抹去既有题目和问答的必要引用快照，历史仍显示“原资料已删除”；删除对应历史或注销账号时按各自生命周期清理。问答历史单独可删除，不产生学习奖励。注销账号先记录可独立存活的清理指令，再执行既有关系数据删除；执行器提交前复核账号/资料状态，防止删除后重建索引。

### 3. 导入与分块保留来源结构

支持文字 PDF、DOCX、Markdown、TXT 与单个公开网页。沿用现有单文件 20 MB、PDF 200 页和解析文本 10 万字符上限；初始建议每用户 100 份资料、总正文 500 万字符、每日 20 次新导入，均为服务端可配置上限，在付费调用前检查。

- PDF 复用 `pypdf` 逐页文本，保留真实页码；扫描件明确提示暂不支持 OCR。
- DOCX 复用现有段落/表格顺序和解压膨胀检查；引用定位使用段落或标题，不能虚构 Word 页码。
- TXT 沿用现有安全解码。Markdown 增加文件签名/文本检查与大小校验，保留标题、代码和表格；HTML 只作文本，不执行脚本，不自动抓取图片或链接资源。
- 网页复用现有公开地址、协议、DNS/内网校验和官方 Tavily Extract，入库实际返回正文并保留原网址、抓取时间和截断信息；不能用模型总结或搜索摘要冒充整页。未取得正文则失败，不能假称已入库。
- 显式“从已有材料加入”先核验归属与可用正文，再复制为独立知识库版本；不能只引用将被临时清理的材料记录。

PDF 优先按页、Markdown 优先按标题分组，再用 `RecursiveCharacterTextSplitter` 分块；Markdown 使用 `MarkdownHeaderTextSplitter(strip_headers=False)` 保留内容标题。初始目标块大小 **1000 字符、重叠 150 字符**，中文分隔符优先，块不跨需要保留的页/标题边界；这些是字符设置，不是模型 Token 数。保存标题层级、原文起止位置、页码、块哈希、解析器与分块策略版本。

导入页面在上传前说明：文件会在服务端保存，文本发送百炼进行向量化，实际检索到的片段交给 DeepSeek 完成学习任务；联网补充不会把原始文件或私有片段自动提交搜索服务。普通联网结果只作本次证据，不自动沉淀知识库。

### 4. Embedding 固定配置，独立适配与计费边界

采用用户指定的百炼 `text-embedding-v4`，第一版固定 **1024 维、cosine 距离**；新增实现 LangChain `Embeddings` 同步/异步接口的适配器，复用 HTTPX 调原生百炼接口，文档和查询分别设置 `text_type=document/query` 与 `dimension=1024`。

不直接依赖默认旧模型的社区包装器，也不把 Embedding 密钥和 Base URL 复用到 DeepSeek。服务端配置独立的密钥、模型、维度、百炼工作空间/地域端点、超时、重试、并发和额度。当前官方端点存在工作空间/地域区别，实施时从实际百炼控制台核对，前端不得覆盖。不能假定固定免费额度或所有地域数据政策相同。

每请求至多 10 段，每段不超过当前官方 8192 Token 限制；字符分块先采用保守字节/Token 上界检查，超出安全界限继续切分，提供方仍拒绝时返回明确错误，不以“1000 字符必为 1000 Token”推断。校验返回索引顺序、数量、有限数值与维度；缺失、错位、NaN 或维度变化都不能发布。

重试仅针对瞬时网络故障、限流和可恢复服务错误，最多 3 次并带退避；认证、余额和配置错误不盲目重试。按账号及配置缓存相同内容，不做跨用户内容缓存。Embedding 请求/Token 单独记账与预留，不消费闯关次数；初始每日上限建议 20 万 Embedding 输入 Token，实际用量回填，无法确认的调用保守保留预留额。中断后尽量复用已登记批次，外部响应丢失仍可能重复计费，不能承诺外部调用恰好一次。

### 5. 单个执行进程持有本地 Chroma

当前官方 Chroma 约束说明本地库不适合多个进程同时写同一路径。因此 API 只鉴权、读写 MySQL 与创建任务，**不打开本地 Chroma**；新增 `python -m app.knowledge.worker` 统一持有 PersistentClient，处理入库、检索、清理、问答和知识库出题。进程锁和数据库执行器租约共同阻止第二个本地索引写入者，路径固定且为私有目录。

进程内限制任务并发和批次大小，初始最多 2 个活动任务；同步 Chroma 操作通过受限线程执行，不能阻塞异步心跳。清理和交互任务优先，入库按小批次让出调度；同一用户的 AI 操作与既有并发限制协同。需要多机扩展时才切 Chroma Server/HttpClient；本期不引入 Redis/Celery，不声称已经实现集群高可用。

### 6. 持久任务覆盖所有新增耗时链路

流程：请求完成身份、格式、额度和参数校验，保存接收完毕的上传文件及资料/任务，立即返回任务 ID；执行进程领取任务；前端每 2～5 秒查询；完成后展示资料、问答结果或关卡。上传本身必须先传完，不能宣称未接收文件便已完成上传。

状态为 `queued/running/succeeded/failed/cancelled`，另有阶段、0～100 进度和可操作错误。任务按账号、类型和幂等键去重，重试关联父任务并复用同一文档/操作身份。进度持久化且不下降；完成才到 100。请求超时、切后台或关闭小程序不等于取消；显式取消后，执行器在下一安全点停止，并在每次付费调用和最终发布前检查取消与租约。

执行器用原子领取、租约、心跳与 fencing token 防止旧执行器提交；重启后只恢复有效检查点，保留已花费预算、首次截止时间及外部调用计数，不能通过重试重新获得额度。入库暂存向量及批次清单可验证后复用；检索证据、生成稿和审核结果分别持久化，失效或超过预算则明确失败。单任务最多 3 次可恢复尝试；建议入库上限 900 秒、问答 180 秒、范围准备 240 秒、出题 300 秒，排队超过 10 分钟明确提示；这些是后台总时限，单次客户端请求仍约 15 秒内返回。

沿用每账号每分钟 10 次实际模型调用和单账号 AI 并发限制；队列等待不提前占住旧出题的 AI 忙碌租约。问答初始每日 20 次，范围准备沿用相应准备额度，出题继续消耗现有闯关额度，所有重试都记录真实调用。Embedding 单独限流。旧进程内后台任务不在本次迁移范围。

**最终关卡发布、幂等操作结果和任务成功必须在同一 MySQL 事务落库**；给现有发布服务增加可选事务适配，保持旧调用默认行为。不能先提交关卡再单独标记任务成功。问答发布同理。必要的恢复查询以任务关联的唯一操作 ID 对账，避免重复关卡、额度和奖励。

### 7. Agent 路由受权限和预算控制

新建知识库检索编排器并复用现有模型/工具预算钩子。现有联网 Agent 在缺少 Tavily 配置时会直接结束，不能原样拿来承担纯知识库路径。

提供三个受控工具：`knowledge_search`、官方 `TavilySearch`、官方 `TavilyExtract`。用户选择的资料范围、版本、账号和联网开关由服务端绑定，模型不能自行扩大权限。

| 用户目标 | 可执行路线 | 依据不足的行为 |
| --- | --- | --- |
| “根据我选的资料” | 必须先检索这些资料；允许补充时再用网页补充 | 不能用网页或模型记忆冒充该资料观点 |
| 私有资料里的具体事实，关闭联网 | 仅知识库 | 明确未找到支持，建议补充资料或改目标 |
| 一般知识或最新动态，允许联网 | Agent 选择知识库、联网或组合 | 说明实际使用来源、时间与未覆盖部分 |
| Tavily 不可用，知识库足够 | 继续用知识库 | 明示联网未完成，不声称已查最新资料 |
| 知识库不可用且问题依赖私有资料 | 失败或依据不足 | 不把网上同名内容当作已经读过用户文件 |

检索先取限定范围内的候选块，去重与控制相邻重叠；默认取约 4 个有效片段，可在 1～12 之间按问题调整，并对选中主题/多文档公平分配。相似度只是召回信号，不当作“事实可信概率”；相关性与答案支持仍需检查。不能保证一次检索覆盖整本长文。

初始预算复用现有边界：检索规划最多 3 次模型调用、最多 4 次工具调用，知识库片段与网页各最多 12 项，拼接上下文总计最多 24000 字符；生成与独立审核另外预留预算，所有实际调用仍计入账号限制。重试、空结果与工具失败也消耗相应预算。

联网参数由目标与复杂度动态决定：简单查询摘要、复杂资料按预算取正文；结果数按覆盖需求调整；国家使用官方 `country` 偏向，城市放入关键词并核验结果地域；全球性知识不强行加地域。没有真实城市筛选参数，也不能把用户语言直接当实际所在地。已有 URL 优先 Extract；需要探索时 Search，再按证据缺口 Extract。采用当前包装器支持的参数白名单与服务端上限。

搜索查询只能包含用户目标中必要的公开主题或安全概括，禁止自动携带文件全文、私有片段、账号标识和问答历史。服务端形成可审计的公开查询计划，约束工具参数并测试私有哨兵文本不外泄；私有事实无法安全抽象时不自动搜索。资料/网页内容均视为数据，不能按其中的指令扩大工具权限或访问范围。

### 8. 引用快照与事实审核

知识库证据使用稳定、无碰撞的片段 ID，绑定文档 ID、版本、块 ID、标题路径、真实页码/段落、原网址与抓取时间；联网证据继续使用现有登记器的真实返回值。模型只返回已登记引用 ID，归属、来源状态和引用元数据由程序填写。

共享证据结构新增明确的可选知识库引用字段；知识库块按现有 `material` 证据语义进入严格审核，保留其原始文件或网页类型作为定位信息。联网补充另标记 supplement。新增 `QuizSource.type=knowledge_base` 与所选文档快照，所有旧枚举与字段默认值保留。不能伪造一份 `Material` 或只靠模型总结绕过多材料校验。

仅知识库证据沿用 `material_only`；真正取得且支持结论的联网补充才按现有规则评估 `source_backed`；旧网页入库时的抓取时间不等于本次联网时间。新知识库问答和出题都采用严格依据规则：没有充分支持时说明不足或失败。用户此前允许的一般主题“未联网核实”降级仍仅按旧流程执行，不据此编造私有文档内容。

来源阅读沿用现有组件，并增加文档标题、版本、块位置及删除状态。出题阶段保留服务端答案隐藏；未作答题不能因预览引用字段而泄露答案或讲解。

### 9. 问答与出题的产品流程

**我的知识库**：资料列表 → 上传文档/添加网页（可显式加入已有材料）→ 进度与失败重试 → 资料详情与分块预览 → 多选资料后“提问”或“生成关卡”。支持单份删除，用户只选就绪资料；不会出现必须逐层选择领域、方向、知识点的长表单。

**知识库问答**：选择资料或明确选择全部就绪资料 → 输入问题并看到默认开启的联网补充开关 → 提交后台任务 → 回答、引用、实际来源状态 → 可查看/删除历史。第一版为单轮问题，问题最长 6000 字符、回答目标上限 2000 字符；不偷偷带历史作为上下文。回答按段落/事实绑定引用，通过独立支持性检查；冲突来源分开说明。无支持时给出“资料不足”，而不是完整但无依据的答案。不生成作答记录、经验、错题或学习报告。

问答页“按这个问题出题”只携带原始问题和原始资料范围，再执行范围准备与用户确认；AI 回答不是新证据。

**知识库出题**：所选资料 + 学习目标 + 联网权限 → 后台准备 → 一层可多选主题卡片（默认推荐主题）→ 用户确认题数/难度 → 后台生成和独立审核 → 现有关卡。准备快照绑定文档版本和权限；删除、改版本或切换联网开关需重新准备，不能悄悄沿用不一致证据。作答、报告、返回首页和历史删除保持现状。

前端新增独立知识库页面/状态模块；已有入口接入，不继续扩大首页文件的业务状态。复用蓝色单调进度条、来源阅读和现有关卡 UI。持久任务按账号和类型保存，退出/切账号清理本地状态并拒绝旧账号迟到响应；切后台暂停轮询、回来恢复。上传用 Taro 原生选择文件与 `uploadFile`，H5 用现有文件选择适配；解析 `uploadFile` 字符串响应与统一鉴权。支持 `.md/.markdown` 扩展名，微信工具与真机都要验收。

### 10. API 与状态契约

以下均在 `/api/v1/knowledge` 下；采用现有成功 envelope 和 HTTP 200，业务数据区分 `kind=knowledge_job`，防止旧客户端把新任务当作 Session。所有接口都核验当前账号，分页与文本长度有上限。

| 接口 | 作用 |
| --- | --- |
| `GET /capabilities` | 功能启用、Embedding/联网可用性和执行器状态；不返回密钥 |
| `GET /documents` | 分页资料列表、状态、就绪/失败信息 |
| `POST /documents/upload` | 接收文件，返回 document_id、job_id 和初始状态 |
| `POST /documents/web` | 提交公开网址，异步提取、分块和入库 |
| `POST /documents/from-material` | 显式复制本账号已有可用材料 |
| `GET /documents/{id}`、`GET /documents/{id}/chunks` | 详情与分页原文片段；原始文件不公开暴露 |
| `DELETE /documents/{id}` | 立即逻辑删除，返回后台清理任务 |
| `POST /documents/{id}/reindex` | 同一内容重建新索引版本；失败保留旧版 |
| `GET /jobs/{id}`、`POST /jobs/{id}/cancel`、`POST /jobs/{id}/retry` | 查询、取消和受额度约束的显式重试 |
| `POST /questions` | 问题、明确资料范围、联网开关，返回任务 |
| `GET /questions`、`GET /questions/{id}`、`DELETE /questions/{id}` | 问答历史、结果与删除 |
| `POST /quiz-preparations`、`GET /quiz-preparations/{id}` | 持久范围准备及结果快照 |
| `POST /quizzes` | 提交范围 ID/版本、选中主题和题数难度，完成后返回原有 Session |

导入、问答、准备和出题提交都接受幂等键；省略新流程联网字段时明确默认为 true，而旧请求默认值保持不变。禁止空资料列表被隐式解释为“所有用户资料”；选择全部必须显式声明，仍只限当前用户就绪资料。

错误区分：404 不存在/不属于当前账号；409 版本变化、已删除或冲突；413 超限；422 不支持格式/参数；429 额度；503 执行器或服务不可用。资料不足作为明确业务结果，与技术失败区分。所有外部错误日志脱敏，前端获得可行动说明，不能只显示“暂时没能完成”。

### 11. TDD 和验收设计

按“写失败用例并保存 RED → 最小实现 → GREEN → 重构和回归”的顺序实施每个新增后端切片。新增后端业务模块的分支覆盖目标至少 90%，关键权限/发布/删除/额度路径逐项覆盖；覆盖率不能替代行为断言。只统计本期新增代码，不为指标改写既有模块。

| 层次 | 关键用例与设施 |
| --- | --- |
| 解析/分块 | PDF 页码、DOCX 表格顺序、Markdown 标题/代码、中文长文边界、重复块、空文档、扫描件、超限及恶意文件 |
| Embedding 适配 | document/query 参数、地域配置、批次/Token 边界、返回乱序/数量/维度/NaN、429/超时/认证、预算和幂等 |
| 存储/索引 | 独立 MySQL 测试库 + 真实临时 Chroma；跨账号、跨版本、阶段失败不可见、重建切换、立即删除及重复清理 |
| 任务可靠性 | 重启、租约过期、旧执行器写回、取消与发布竞态、付费后中断、唯一发布、单调进度、第二执行进程拒绝写入 |
| Agent/问答 | 纯知识库、纯联网、组合、关闭联网、缺 Tavily、资料不足、冲突引用、越权工具、提示注入、私有内容外泄 |
| 出题兼容 | 多资料/多主题引用、范围失效、服务端隐藏答案、独立审核、最终发布事务、额度、作答奖励、旧历史和旧入口 |
| 前端/联调 | API 契约、账号切换、恢复轮询、上传取消、空态/错误、窄屏、引用定位、从问答出题、旧流程回归 |

单元测试用受控 HTTP/LLM/Embedding 替身，断言实际请求与失败路径；不把所有持久化都 Mock。MySQL 与 Chroma 集成测试必须隔离到测试数据库和临时绝对目录，防止接触用户索引。依赖兼容先检查当前 Python 3.13/Windows 与 LangChain 锁文件，安装锁定版本后执行测试，不预先宣称最新版本组合一定兼容。

自动验证通过后，另安排真实百炼、DeepSeek、Tavily 小样本联调和人工逐项核对：中文长文、英文技术、Markdown、PDF/DOCX、网页、文档外新知识及冲突信息；记录耗时、调用量、回答/题目与实际引用。微信开发者工具和真机验证上传、轮询、切后台及作答报告。自动测试结果与用户实际验证分开登记，不能把模拟调用等同于真实模型正确性。

2026-10-18 已通过 Context7 查询 LangChain、Chroma、Taro、百炼相关资料。Context7 对百炼 v4 的特定参数覆盖不足，另外查阅官方 API。实施时再次核对锁定版本，仅引用官方接口实际支持的参数。

- [LangChain Chroma 集成](https://docs.langchain.com/oss/python/integrations/vectorstores/chroma)：独立 `langchain-chroma` 包与持久客户端。
- [Markdown 标题分块](https://docs.langchain.com/oss/python/integrations/splitters/markdown_header_metadata_splitter)：标题元数据与递归分块组合。
- [Chroma 系统约束](https://cookbook.chromadb.dev/core/system_constraints/)：[客户端模式](https://cookbook.chromadb.dev/core/clients/)说明本地持久化边界；[多用户集合示例](https://cookbook.chromadb.dev/strategies/multi-tenancy/naive-multi-tenancy/)不能替代应用鉴权。
- [百炼同步文本向量 API](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)：v4 维度、批次、Token 上限、原生 text_type 与区域/工作空间端点。
- [官方 Tavily Search](https://docs.langchain.com/oss/python/integrations/tools/tavily_search)、[官方 Tavily Extract](https://docs.langchain.com/oss/python/integrations/tools/tavily_extract)：维持当前项目官方双工具与动态参数设计。
- [Taro 文件选择](https://docs.taro.zone/docs/apis/media/image/chooseMessageFile)、[文件上传](https://docs.taro.zone/docs/apis/network/upload/uploadFile)：原生文件选择、上传任务与响应处理。
- [FastAPI 后台任务](https://fastapi.tiangolo.com/tutorial/background-tasks/)：现有进程内任务不提供本方案要求的跨重启任务恢复。

## Risks / Trade-offs

- [本地 Chroma 只有一个持有进程，执行器宕机时知识库暂不可用] → 持久队列、心跳报警、重启恢复；旧出题入口独立。规模增长再切服务模式。
- [检索相关不代表事实支持，模型仍可能错误引用] → 原始片段快照、逐项支持审核、明确不足与冲突；真实样本人工核对。
- [云端 Embedding 与默认联网带来费用和数据传输] → 上传说明、独立配置与额度、受限查询、关闭联网选项；不承诺免费或完全本地运行。
- [大文件、重叠块与重建会增加时间和存储] → 文件/账号额度、小批量、版本去重、阶段进度、旧版保留及暂存清理；不承诺固定秒数。
- [MySQL 与向量文件不能跨介质原子提交] → 暂存版本 + 最后数据库指针发布 + 幂等清理/恢复，历史查询始终按活动版本过滤。
- [新来源字段可能影响严格旧读取器或旧二进制回退] → 可选字段、全链路契约测试；回退目标必须保留新来源读取能力，不能承诺发布过知识库关卡后任意降回未识别该类型的旧版本。
- [原始资源与源码仍有进行中的用户修改] → 实施先记录差异与回归基线，最小增量，不覆盖或回滚用户改动。

## Migration Plan

1. **确认后再开始。** 先保存当前工作区和核心功能测试基线，核对当前 Alembic head；本方案不安装依赖、不执行迁移、不改运行中数据。
2. 按现有锁定方式新增兼容依赖与配置示例；功能默认关闭，缺少知识库配置或可选依赖不能令旧应用启动/健康检查失败，采用惰性初始化。
3. 创建独立表、索引、唯一约束和账号清理 outbox；迁移只增加结构，不改写旧材料、关卡、报告，不自动将临时资料保留为私有库。
4. 配置百炼工作空间/地域端点和私有持久化目录；开发/测试/生产分离，目录不进 Git。启动脚本在启用功能时管理单独执行器及其日志，关闭后不影响原后端。
5. 各切片通过 TDD、真实存储集成和旧功能回归后，启用受控账号联调，完成微信工具/真机和来源准确性验收，再放开入口。
6. 备份 MySQL、原始文件和一致的 Chroma 检查点；新 Embedding 配置建新集合，验证后切换，保留可回退旧索引。
7. 回滚先关闭新提交入口、停止领取新业务任务并处理在途任务；保留能读取新快照的后端和历史 UI。清理执行能力须独立保留，不能因功能关闭遗留账号删除数据。默认保留新表与索引，禁止有数据时直接执行破坏性 downgrade。
