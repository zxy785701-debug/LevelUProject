## 本机运行故障修复

用户在微信页面遇到“解析暂时失败”。本机8000健康检查200；实际日志为 MySQL `1054 Unknown column ai_operations.retrieval_log`，运行库停在005而自动加载的新代码已需要006。不是后端连接中断。

2026-10-14 19:23，先用mysqldump完整备份本机运行库到被忽略的 `backend/logs/db-backups/before-grounding-20261014-192312.sql`（149210字节），再执行已测试的增量迁移：`005_material_scope_handoff` → `006_retrieval_audit`。已查询确认新增字段可用，没有删除或重写学习数据。维护入口 `backend/scripts/backup_migrate_local.py` 不在命令行暴露数据库密码。

当时Tavily尚未配置；随后用户填入密钥，配置读取已确认生效。首次真实请求返回401，经排查是代码将SecretStr直接交给SDK，SDK使用了脱敏星号而非实际凭证，并非用户密钥填写问题。Search/Extract构造处已修正；新增传输层断言先失败、修复后通过，相关43项回归和最终329项完整回归通过，真实Search与Extract均取得结果。

网页对比样例初轮资料不足；第一轮重测虽出题但偏向安装/调用，不能算方向通过。随后让原始说明成为材料范围的focus，并在检索消息开头强调原始任务；第二轮因资料不足停止，第三轮实际调用官方文档的full与focused Extract，生成了定向片段与全文区别的题目。完整调用链、被替代的题库及失败结果分别保留在 `acceptance-20261014-sdkfix` 和 `acceptance-20261014-retest1/2/3`，只有受影响项重测，未增加预算或更换模型/供应商。

真实失败探针另存 `live-runs/failure-probes-20261014/`，不计入20例：纯403网址返回TAVILY_EMPTY且未猜正文；附独立TaskGroup主题移交未核实范围并要求确认，确认后实际模型输出未通过Schema校验，以MODEL_INVALID_OUTPUT终止，不能伪报降级生成成功；虚构框架检索结果与主题无关，最终INSUFFICIENT_KNOWLEDGE，未发布虚构语法题。

用户随后运行启动命令仍提示迁移失败，但迁移标准输出明确成功、错误日志为空。复现发现PowerShell5.1在日志重定向后仅轮询HasExited会丢失ExitCode，成功0和失败7均成为null；启动脚本误将null判为MySQL失败。改为对迁移使用 `Start-Process -Wait -PassThru`，并区分未知退出码。两个真实子进程回归通过，原启动命令已完成迁移、后端启动及小程序编译。依据：[微软Start-Process文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1)。

## 微信人工验证清单

在开发者工具导入 `frontend/`，使用最新 `frontend/dist/`，普通编译后登录：

1. 首页输入关键词，核对搜索/读取/等待阶段，选择领域、方向和知识点；显式确认前不生成关卡。
2. 输入网址和说明，读取指定页面；预览内容与页面一致，联网补充默认关闭，切换后使用正确设置。
3. 生成时返回首页，等待后恢复原操作；断网重进仍恢复同一任务，不重复扣关卡额度。
4. 作答后查看逐题来源，核对外文、长链接、未知日期、截断标识、文档页码与字幕时间；旧历史显示未记录状态。
5. 核对联网不可用时的“未联网核实”，纯网址失败提示补充正文或明确主题，范围仍须确认。
6. 在真机重复两类输入、来源和恢复，保留设备/基础库版本、截图及实际通过/失败结果。真机需要可访问的 HTTPS API 和合法域名配置。
