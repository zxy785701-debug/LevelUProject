# 联网出题数据库迁移

迁移版本 `004_quiz_grounding` 接续 `003_materials_analytics`，使用原有 Alembic 启动迁移入口。后续 `005_material_scope_handoff` 增加材料任务可空 `preparation_id` 外键，用于不可读网页附明确主题时转入未核实确认；不伪造材料 ID，不重复扣准备额度，准备清理时该关联设为空。`006_retrieval_audit` 为操作增加可空检索审计 JSON，旧行保持空，不虚构历史用量。

- 新表 `topic_preparations` 保存用户输入、版本、状态、证据与范围快照、过期时间。用户与幂等键唯一，同一操作只关联一份准备；账号删除通过外键级联清理准备内容和操作。
- `ai_quotas.topic_prepare_count` 默认 0，使用原有上海时区每日重置和身份摘要额度表。注销保留当天计数，重新注册不会获得额外准备次数。准备次数的原子占用在准备生命周期任务接入。
- `ai_operations` 新增可空的阶段、期限，以及默认 0 的等待秒数、模型/工具/页面次数。旧操作的结果、计费状态及历史内容保留，新计数不追溯虚构旧调用。
- 所有新增非空旧表列都有数据库默认值；已有材料和题库 JSON 无需重写。升级为增量操作，禁止破坏性 downgrade。回退应用时保留兼容来源快照的版本，通过功能开关暂停新入口。

上线前备份业务库并先在测试环境升级；确认 Alembic 版本为 `006_retrieval_audit` 后部署配套接口。MySQL DDL 不能依赖事务整体回滚，异常中断须检查已生效列与迁移版本，再按实际状态修复，不能直接删除表重试。

验证入口：在 `backend` 执行 `.venv/Scripts/python.exe -m pytest tests/test_grounding_database.py -q`。该测试会重建专用测试库表，只能串行执行；执行前核对 `database_testing`、实际数据库名与配置一致、后缀 `_test`、与业务库不同，并拒绝包含未知表的库。业务迁移不包含测试重建逻辑。

官方依据：[Alembic 操作说明](https://alembic.sqlalchemy.org/en/latest/ops.html)，新增列使用 `server_default` 处理存量行。
