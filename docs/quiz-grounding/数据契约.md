# 数据契约

此文随实现更新；当前是模型定义，接口接入由后续任务完成。

- `GenerateRequest` 的文本、材料和准备记录三种来源互斥。准备记录必须同时有版本、候选、方向及非空知识点列表；模型层检查结构，服务层继续检查本人、有效期及保存范围的归属。
- 材料的 `point_ids` 是原分段标识，主题的 `scope_point_ids` 是候选方向内的知识点，不能混用。主题采用后台模式；材料显式 `execution=background` 时使用后台模式，未传时保留同步契约。
- Search 参数不允许任意额外字段或凭证；结果数为 1–10，时间范围与起止日期互斥，国家偏向仅适用于 general。城市以查询内容表达。
- Extract full 模式禁止 query/chunks_per_source；focused 模式必须提供二者。每次最多 3 个 HTTP(S) 网址，外部读取前还需执行公开地址验证。
- 原网页可携带 `learning_instruction`，不能因网址输入丢失学习目标。
- 来源记录区分 snippet/full_extract/focused_extract/material，分别保存实际取得时间、未知或真实原文日期、获取状态与截断状态。网络片段必须有网址和取得时间；历史材料允许缺省这些新增字段。
- 已取得资料的知识点必须有来源标识；标識合法不等于内容支持题目，后续独立审核检查事实支持。范围选择必须在对应候选和方向下查找。
- `QuizDraftResult` 明确区分有效 3/5 题草稿和知识不足；知识不足不携带伪造题库。审核 supported 必须提供依据标识。
- `GenerationOperation.kind=generation_operation` 与最终 Session 区分；就绪准备必须有范围和来源状态。接口序列化负责避免提前暴露答案。
- 题库及逐题 grounding、learning_scope 都可缺省。缺少历史状态不能当作已核实；主题来源不使用伪造 material_id。
