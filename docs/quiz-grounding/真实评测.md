入口：`backend/scripts/live_grounding_eval.py`；20例：`backend/scripts/grounding_eval_cases.json`。2026-10-14最新尝试已完成20例完整生成，用户对60题核对请求直接回复“正确”，已按总体确认登记人工字段并通过汇总；见[结果汇总](live-runs/review-20261014.md)。未收到逐项表单导出，确认粒度明确保留，不能把结构和引用ID检查当作人工证据。

输入涵盖 Harness Engineering 和花少2各3例、4个指定网页、英文/双语、简单/复杂知识、全球/国家/城市和同名地域消歧。没有生产主题特例。范围选择与来源支持需要分别确认，模型的审核结果不等于人工验收。

## 配置检查

仅在本机 `backend/.env` 配置 `TAVILY_API_KEY`，保留现有 DeepSeek 设置，不把凭证写入前端或对话。先执行：

```powershell
cd backend
.venv/Scripts/python.exe scripts/live_grounding_eval.py --run-id acceptance-20261014
```

缺凭证退出2，写 `docs/quiz-grounding/live-runs/<run-id>/manifest.json`，`executed=false`；不连接数据库、不调用模型。配置就绪也只检查，必须显式 `--run` 才产生真实请求。

## 执行与确认范围

先停止其他使用 `levelup_test` 的测试/测试服务。命令保留正常5/7次模型预算、每分钟3次限制和240/300秒期限，可能出现额度等待，不提高额度来伪造成功：

```powershell
.venv/Scripts/python.exe scripts/live_grounding_eval.py --run-id acceptance-20261014 --run
```

在交互终端逐例展示实际取得的范围，由操作人输入 `candidate_id focus_id point_id1,point_id2`。网页材料输入所选片段ID，默认不补充。输入 `skip` 留待确认，不算生成成功。

非交互环境不自动挑选方向：先保存准备结果，然后提供 `--selections selections.json`；文件按case id保存确切选择。主题确认必须包含 `confirmed=true`、当前 `preparation_id` / `scope_version`、`candidate_id`、`focus_id`、`scope_point_ids`；材料包含 `confirmed=true`、当前 `material_id`、`point_ids` 和 `supplement`。当前准备文件在每例JSON中。伪造/旧版本选择拒绝，过期准备应新建run id并重新确认。本轮选项由Codex评测操作人按样例原意查阅真实范围后明确填写，`selection_actor`记录操作者；属于测试输入，不冒充用户亲自选择或最终人工验收。生产用户流程仍每次显式确认。

自动化运行明确加 `--non-interactive`，保存范围后等待选择文件，不在没有可读stdin的终端提示输入；EOF同样保留待确认状态。范围确认与最终逐题人工证据核对分开记录。

可以 `--case harness-1` 指定样本。相同run id会跳过已完成生成，等待确认的自身测试账号保留以恢复；不储存登录token。已完成样本保存题库和来源快照后仅删除自身测试账号。结束后 `--cleanup` 清理该run的剩余测试账号；没有整库清空操作。

## 实际证据与人工核对

每例JSON保存原输入、准备/材料、确认范围、逐题答案与讲解、真实引用、Search/Extract实际参数和调用链、获取状态、工具用量、实际模型/工具/页面次数、结构化响应token元数据和时延。`api_timings`记录各阶段实际执行时间，工具调用链记录工具耗时；`elapsed_seconds`含操作人的确认等待，不能当纯模型耗时。入口通过ASGI执行真实服务调用，HTTP后台体验另由浏览器验证。恢复会保留先前用量记录。没有返回token元数据的请求保持未知，不能用0冒充用量。所有模型尝试以数据库计数为准，provider usage按实际返回保留。

操作人必须查阅真实引用片段，并填写每例 `human_review`：范围是否符合原意，每题是否在范围内、有无矛盾；`source_backed`逐题检查引用能否支持正确答案和讲解。热梗多数方向额外逐题标记是否实质考查梗/出处/场景，不能用节目年份、嘉宾名单冒充。

```powershell
.venv/Scripts/python.exe scripts/live_grounding_eval.py --run-id acceptance-20261014 --assess
```

缺结果、缺人工核对、结构错误、虚构引用不能通过；20次完整结果、至少18次范围正确、所有有依据题得到支持，且热梗多数样本至少2题实质覆盖，才可判通过。`unverified`单列，不能计作联网成功。自动汇总只是完整性与人工判定汇总，不自行声称事实已被人审过。

`--failure-probes`另运行 `grounding_eval_failure_cases.json` 中的纯不可读页、带明确主题说明和稀疏资料探针。必须记录供应商实际返回，服务方若读取到内容也不能伪报失败。这些探针不能用来凑20次完整生成；正常20例的汇总不加该参数。不得将受控测试结果混入真实20例。本轮真实记录在 `live-runs/failure-probes-20261014/`，具体成功/失败边界见验收记录。
