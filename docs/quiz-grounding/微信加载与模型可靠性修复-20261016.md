# 微信加载与模型可靠性修复

日期：2026-10-16。

## 问题与修复

### 微信图片属性过长

`mini.postcss.url` 仅控制样式中的图片。组件通过 import / require.context 引入的图片仍使用 Taro 默认的 2 KB 内联阈值，导致小图标以 base64 字符串传入 `Image.src`。当前安装的 Taro 4.3.0 在计算图片阈值时使用 `limit || defaultValue`，因此数值 `0` 不能关闭组件图片内联。

在 `frontend/config/index.ts` 的 `mini.webpackChain` 中，将图片规则设为 Webpack 5 的 `asset/resource`，保留原图片和导入方式，输出本地文件路径。增加 `npm run check:assets`，同时检查小程序 JavaScript 无内联图片、全部 PNG 已输出且内容大小一致。

同一开发构建比较：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| JavaScript 内联图片 | 44 | 0 |
| 内联图片字符串累计字符 | 66,464 | 0 |
| 最长图片属性字符 | 2,750 | 改用本地文件路径 |
| JavaScript 总字节 | 496,126 | 431,020 |
| 输出 PNG | 部分小图标内联 | 全部 49 张 |

JavaScript 减少约 13.1%。这不是启动耗时下降比例；用户日志中的 9,710 ms 尚未在微信模拟器或真机中重新测量。

### 偶发模型连接失败与超时

本机操作状态和用户日志确认了上游 503 / 连接失败、模型响应超时；同时，有些请求已返回 token 用量，却没有通过现有校验。旧日志未保存具体校验位置，无法据此追溯那两次响应的确切不合格字段。

修复模型网关与检索 Agent：

- 临时连接故障、超时以及 HTTP 408/409/429/5xx 才自动重试；认证等永久错误及时结束。
- 有效 `Retry-After`（秒数或 HTTP 日期）及 `retry-after-ms` 优先于默认指数退避。等待要求超过 60 秒时结束本轮，不提前重试；异常值使用有界默认退避。
- 检索规划使用配置允许的实际请求次数，默认最多 3 次；每次仍检查账号、阶段和模型预算，不重新执行已完成的资料工具请求。
- 每次模型请求同时限制完整耗时与 HTTP 读取等待，避免连接持续返回保活数据时突破配置期限。当前 30 秒配置与准备/生成的阶段总期限保留。
- JSON 或业务校验失败后，下一次请求增加完整重生成与约束修正提示。Pydantic 错误只提取 Schema 已声明的字段位置；不向日志或修正消息写入原始模型回复、用户正文、异常全文、凭证或未知额外字段名。
- 新日志 `model_attempt_failed` 记录操作、Schema、次数、错误码、内部失败类别、安全字段位置、HTTP 状态、耗时及是否重试。保留既有 `model_response` 用量日志格式，兼容评测工具。

## 真实服务抽测

使用已有 DeepSeek 配置与真实 Tavily 服务，在隔离测试库创建临时账号，执行公开的 HTTP 学习示例。微信登录在此测试中使用测试替身，学习范围由自动测试操作方选择，不作为人工内容验收。

- 学习范围准备成功：45.87 秒，含真实检索和范围整理。
- 确认范围后，3 题出题与独立审核成功：9.04 秒，结果状态 `source_backed`。
- 验证未答题时答案与讲解隐藏，整轮仅扣一次关卡额度。
- 测试账号已删除，未修改真实用户学习记录。结果：`backend/test-results/model-live-smoke-20261016.json`。

一次真实成功不能证明供应商之后不会再返回 503。修复提供有界恢复及可定位日志，供应商持续不可用时仍返回明确失败，不跳过事实审核。

## 本机使用

最终微信构建已输出到 `frontend/dist`。在微信开发者工具重新编译；若正在运行旧的持续编译进程，先重新启动 `npm run dev:weapp`，让它重新加载构建配置。若工具仍显示旧图片警告，清理编译缓存后再次编译。

本机后端脚本支持自动加载 Python 改动。自行启动且没有自动加载时，需要重启后端才能使用修复。
