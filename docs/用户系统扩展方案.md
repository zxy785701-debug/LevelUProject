## 1. 已阅读资料与现状

已阅读需求分析、方案设计，以及 `prototype/` 的页面定义、共享样式、交互脚本、页面清单、验收说明与截图，覆盖 69 个业务页面和关键状态；并检查了现有后端、`frontend/` 的学习流程、账户入口、本地存储和测试。

原需求及设计中的“不做登录、不引入数据库”属于早期 MVP 边界，本次按用户的新要求扩展。技术栈继续使用 Taro 4、React、TypeScript、FastAPI、Pydantic 和现有 AI 网关。

## 3. 本次建议完成的范围

本节及后续设计需要随整份方案一起人工确认。

### 3.1 微信账号与会话

- 小程序调用 `Taro.login` 取得临时 code；后端调用微信 `code2Session`，取得可信身份，再签发自己的登录凭证。
- 首次微信登录自动创建业务账号，无需单独填写注册表单；以后登录关联已有账号。
- 使用 `(appid, openid)` 唯一识别微信账号；UnionID 可为空，有返回时补充保存。本期不做跨小程序账号合并，也不相信客户端提交的 openid、unionid 或 user_id。
- 使用随机、不透明的 Bearer 登录凭证，数据库仅保存凭证摘要。初始有效期设为 7 天，可配置；退出登录立即撤销当前会话。
- 启动时验证业务登录态；过期、撤销或无效即回到 A02。`Taro.checkSession` 不能替代后端业务凭证校验。
- 登录页允许查看用户协议、隐私说明；健康检查、登录接口之外的业务 API 均要求鉴权。不能通过返回、切换页面、直接请求旧接口绕过。
- 登录失败可重试，不产生半成品账号；同一微信账号并发首次登录只创建一个用户。

### 3.2 用户资料和个人中心

- 默认昵称和现有默认头像可以直接使用，不把资料填写作为进入小程序的条件。
- 点击 A01 现有头像位置，通过 `open-type="chooseAvatar"` 主动选择；点击昵称位置编辑，使用 `type="nickname"` 和表单提交读取最终值。保存、失败和重试沿用现有弹层与确认按钮样式，不新增独立资料页面。
- 微信返回的头像地址是临时文件路径，上传后才能长期保存。后端校验实际图片格式、大小和尺寸，重新编码为头像图片；昵称校验长度和空白内容。
- 初期头像图片与资料均存 MySQL，避免依赖本机临时文件或额外对象存储。图片通过登录后的下载接口取得，再由前端显示本地临时路径；替换头像后清理旧图片及缓存。
- 个人中心展示真实昵称、头像、等级、XP、金币、完成主题数和连续学习天数；取消示例数值。

### 3.3 云端学习记录、错题和分析

- 按用户保存生成的关卡、题目、学习轮次、逐题作答、已保存进度、完成结果、学习报告和错题状态。
- 支持历史列表、已有筛选、记录详情、继续未完成学习、重玩、错题列表、错题重温及当前已实现的分析维度。
- 另一台设备登录同一账号后，可从服务端恢复已经保存的进度和记录。断网时保留尚未提交的本地选择并提示重试；提交成功前不显示已入账奖励。
- 完成学习先保存结果，再生成 AI 报告；报告失败不丢学习记录、错题或奖励。
- 已有报告直接读取，不重复调用 AI。重玩和错题练习使用已存题目，不重新调用 AI 出题。
- 旧游客数据保留在原本机存储中，不自动迁移到账号，不计入云端统计或金币。它们缺少可信身份和服务端判分依据；本期不开发历史游客数据认领功能。
- 账号缓存按用户隔离。退出或切换账号时清除当前账号的凭证和页面状态，旧账号的延迟响应不能写入新账号缓存。

### 3.4 XP、金币与统计口径

- 沿用现有规则：每道新关卡题首次答对 `+10 XP / +2 金币`，答错不扣已有奖励，每累计 100 XP 升一级。
- 判分由服务端读取已存正确答案完成。首次作答提交前，题目接口不下发正确答案和解析；提交后返回判分及该题讲解，保持现有即时反馈体验。
- 一道题的首次答案提交后锁定；相同请求重试返回原结果，不同答案的二次提交被拒绝。答案、奖励流水、余额和错题变更在同一事务中保存。
- 奖励受数据库唯一约束保护，重发请求、刷新、断点恢复、并发提交、重玩、错题重温均不重复发放。客户端的 mode、得分或金币字段不能决定奖励。
- XP、金币按已成功提交的首次正确答案实时累计，包含尚未完成的首次学习；主题数、总体正确率和连续学习天数按已完成的首次学习统计，避免重玩刷统计。
- 总体正确率按有效答题总数加权计算。连续学习及每日额度以 `Asia/Shanghai` 自然日为准，时间戳统一保存为 UTC。
- 本期金币只展示和累计，不新增消费、兑换、支付或提现功能。

### 3.5 账户管理

- 在 A03 / E10 现有设置及确认流程中接入：退出登录、清理本机缓存、清空错题、导出当前账号学习记录、注销账号。
- 清理本机缓存不会删除云端记录；清空错题只清除错题本状态，不删除原始学习记录、余额或奖励流水，不能因此再次领奖。
- 导出只包含当前账号的数据，沿用已有 CSV 导出入口。
- 注销须明确二次确认，并通过新的微信登录 code 验证当前身份；删除资料、头像、学习数据，撤销所有会话。其他正在进行的写入须检查账号状态，不能在注销后重新生成数据。
- 为防止当天反复注销、注册重置额度，注销后仅保留当期防刷计数及带密钥摘要的微信身份标记，额度周期结束后自动清理；隐私说明明确此用途及保留时间。重新注册不恢复已删除学习数据。

### 3.6 本期不扩展的功能

知识库与 RAG、文档/网址/视频解析、好友/PK/排行榜、会员/订单/支付、装扮、成就、语音及周期 AI 报告仍按现有状态保留入口，不因本次账号扩展实现整套原型的未来功能。登录页权益文案只描述本期实际提供的能力。

H5 用于本地预览和自动化测试；正式用户登录只支持微信小程序。自动化测试可以替换微信与 AI 外部服务，但不提供可在正常运行环境绕过微信登录的测试接口。

## 4. AI 防刷规则细化

| 规则 | 设计 |
| --- | --- |
| 新关卡每日额度 | 每账号 10 次；实际开始调用模型即占用 1 次；模型失败或客户端取消不返还，避免失败重试刷成本 |
| 分钟限流 | 每账号每滚动 60 秒最多 3 次实际模型调用；网关内部重试也计数；读取记录、判分和读取已缓存报告不计数 |
| 并发限制 | 出题、报告共同使用每账号 1 个进行中操作的限制 |
| 报告重试 | 每份已完成学习记录初始最多 3 次生成操作，含首次和 2 次手动重试；每次操作的内部模型重试仍受分钟限流约束；成功后永久复用该份结果 |
| 幂等提交 | 请求携带操作标识；同用户、同标识、同参数的重试复用状态或结果，同标识但不同参数拒绝执行 |
| 配额扣减 | 身份失败、参数校验失败、内容预检失败、已有结果及重复请求不额外扣减；模型已经开始运行的操作占用额度 |
| 存储与并发 | 计数、操作状态、占用和过期恢复均存 MySQL，用事务及唯一约束保护；不依赖单进程内存计数 |
| 故障恢复 | 不在模型网络调用期间持有数据库长事务；操作带超时与占用到期策略，进程退出后可识别失败操作，避免永久锁定及自动重复调用 |
| 登录入口 | 增加可配置的按 IP 登录频率限制，初值每分钟 30 次；只信任部署明确配置的代理地址来源 |

所有阈值通过后端配置管理。前端展示剩余额度及限流提示，后端才是最终执行者；不能只禁用按钮。日志记录操作、状态、调用次数及服务商返回的 usage（如有），不记录密钥或完整登录凭证。本期按次数控制，不实现计费或每日金额预算。

## 5. 技术与数据设计

### 5.1 MySQL 与迁移

- MySQL 8.0+，使用 InnoDB、utf8mb4；SQLAlchemy 2.x 管理模型与事务，PyMySQL 作为驱动，Alembic 管理版本化迁移。
- 正常运行库与自动化测试库必须不同，例如 `levelup`、`levelup_test`；名称及连接信息由本地配置指定。
- 所有涉及持久化、约束、事务和并发的自动测试连接真实 MySQL，不能使用 SQLite 或内存数据库替代。
- 启动准备步骤执行迁移到最新版本，包含全新数据库建表和已有版本升级验证；MySQL DDL 不按完全可回滚事务假设处理，迁移前提供备份说明。
- 测试启动校验测试库与业务库不同，且符合专用测试库配置；只清理专用测试库的数据，不重置业务库。正式服务使用业务权限账号，建库和迁移权限单独说明。

### 5.2 主要持久化对象

| 对象 | 保存内容及约束 |
| --- | --- |
| 用户与微信身份 | 用户资料、账号状态、appid/openid 唯一约束、可空 unionid |
| 登录会话 | 用户、凭证摘要、有效期、撤销状态 |
| 用户头像 | 用户所属、已校验图片、类型与版本 |
| 关卡及题目 | 所属用户、输入材料、生成内容、正确答案与解析 |
| 学习轮次及作答 | 所属用户、题目来源、由服务端决定的练习模式、进度、首答、用时及完成状态 |
| 奖励流水及余额 | 用户、题目、奖励来源唯一键、XP/金币及事务内更新的累计值 |
| 错题状态 | 用户、原题、待复习/已掌握状态、最近复习结果 |
| 学习报告 | 已完成轮次、输入摘要、生成状态、正文及复用依据 |
| AI 操作与额度 | 用户、幂等标识、参数摘要、操作状态、占用截止时间、日额度及模型调用时间 |
| 同意记录 | 用户同意的协议/隐私版本与时间 |

每次查询和修改都从已验证会话取得 user_id；即使猜到其他人的记录 ID，也不能读取或修改其数据。数据库关系和删除顺序会在首个迁移中明确。

## 7. TDD 与验收标准

### 7.1 后端执行方式

每个功能切片执行“失败测试 → 最小实现 → 测试通过 → 重构回归”，保留对应测试结果。数据库行为用真实 MySQL 验证，微信及 AI 的网络边界用可控替身模拟成功、失败、超时和重复响应；替换外部服务不跳过鉴权和业务规则。

| 功能 | 必须验证的行为 |
| --- | --- |
| 数据库 | 新库迁移、版本升级、约束、事务回滚、专用测试库误配置拦截 |
| 微信登录 | 正常/首次/重复/并发登录、无效 code、微信错误、缺少 unionid、凭证到期及撤销、错误响应不泄露密钥 |
| 强制鉴权 | 所有业务路由未登录被拒绝；越权读写被拒绝；失败鉴权时 AI 调用次数为 0 |
| 用户资料 | 默认资料、合法编辑、昵称边界、头像伪造格式/超限、账号隔离 |
| 出题额度 | 第 10/11 次、滚动分钟边界、跨自然日、内部重试计数、并发抢占、重启后额度保留、失败及取消计数、幂等复用和参数冲突 |
| 学习与奖励 | 单/多选/判断判分、答案锁定、同请求重试、并发提交、奖励唯一、事务失败不出现部分入账、恢复/重玩/复习不重复奖励 |
| 历史与分析 | 用户隔离、分页筛选、完成与未完成口径、加权正确率、连续天数、UTC 与上海日期边界 |
| 错题 | 错题生成、重复更新、复习状态、清空不重置奖励、不删除原始历史 |
| 报告 | 只能引用本人已完成记录、客户端伪造统计无效、成功缓存、并发只调用一次、重试上限、失败不影响学习记录 |
| 账户管理 | 导出范围、缓存与云端删除区别、退出撤销、注销身份复验、数据删除、在途写入拦截、当日注销重注册不能刷新额度 |

涉及并发的测试使用不同数据库连接和事务，验证数据库实际行为；不以同一个会话对象的串行调用代替并发验证。新增及修改的后端功能均提供测试与覆盖率报告，不以单纯追求覆盖率替代关键断言。

### 7.2 前端与整体联调

- 前端单元测试覆盖登录态恢复、401 回登录、接口凭证、账号缓存隔离、重复提交和失败恢复。

## 8. 确认后的具体开发步骤

1. **建立可运行基线与测试隔离。** 保留工作区已有修改；核对实际 MySQL 连接与版本，配置业务库/专用测试库，完成现有测试基线，记录可复现的启动与测试方式。
2. **先测试数据库、微信登录和鉴权，再实现。** 增加依赖、迁移、用户/身份/会话模型、微信适配器、统一鉴权、退出和用户隔离测试。将现有 AI 接口纳入鉴权。
3. **先测试资料、个人统计和账户管理，再实现。** 完成默认资料、昵称、头像、协议记录、导出、清理及注销规则。
4. **先测试学习数据和奖励，再实现。** 将出题结果、作答、进度、错题和奖励迁到服务端，保证事务一致和重复请求安全，接入历史及分析查询。
5. **先测试额度与报告，再实现。** 完成 MySQL 额度/并发/幂等控制、失败恢复、可信报告输入、缓存与重试限制；覆盖进程重新创建后的行为。
6. **扩展 `frontend/`。** 按 A02/A01/A03/E10 及 L/R 原型接入真实登录、资料、服务端学习、云端记录与统一错误恢复，替换本机统计权威来源，隔离账号缓存。
7. **联调、回归与交付。** 跑后端完整 MySQL 测试、前端检查及端到端测试，核对原型和微信构建，执行可行的真实服务联调；更新配置样例、启动说明、迁移说明及验收记录，交付可运行项目。

步骤 2–5 均按功能切片执行 TDD，不在全部代码写完后补测试。后续实现所用框架/API 在编码前继续按安装版本核对官方资料。

## 9. 开始开发所需本地配置

- MySQL：地址、端口、业务库、测试库，以及对应账号权限。数据库密码保存在被忽略的本地环境文件中，不需要在聊天里发送。
- 微信：真实小程序 AppID、后端 AppSecret；AppSecret 仅放 `backend/.env`，不能放前端、提交 Git 或输出到日志。
- AI：沿用现有后端 DeepSeek 配置，不把密钥移入小程序。
- 发布运行：后端 HTTPS 地址、微信 request/uploadFile/downloadFile 合法域名；本地微信调试与正式发布的配置区别写入运行说明。

会提供这些新增配置的 `.env.example`，不覆盖已有 `.env` 中的密钥。没有真实微信凭据时可以完成可控服务替身下的开发与测试，但真实微信联调仍需配置齐全后验收。

## 10. 已核对的官方依据

通过 Context7 查询官方资料，并结合项目已安装的 Taro 组件类型核对可用接口；以下是相关官方入口，开发时继续针对具体 API 核对。

- [微信小程序登录流程](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login)：code 在后端交换身份，后端建立自定义登录态，session_key 不向客户端下发。
- [微信 code2Session](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)及 [UnionID 机制](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/union-id)：openid 用于当前小程序身份；unionid 按绑定条件和实际返回保存。
- [微信头像昵称填写能力](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile)：主动选择头像、填写昵称；临时图片需上传持久化，昵称提交需考虑异步检查。
- [Taro.login](https://docs.taro.zone/docs/apis/open-api/login/login)、[Button](https://docs.taro.zone/docs/components/forms/button)、[Input](https://docs.taro.zone/docs/components/forms/input)、[Form](https://docs.taro.zone/docs/components/forms/form)、[uploadFile](https://docs.taro.zone/docs/apis/network/upload/uploadFile)：对应登录、chooseAvatar、nickname、表单提交与上传接口。
- [FastAPI 安全依赖](https://fastapi.tiangolo.com/reference/security/)及 [测试时替换依赖](https://fastapi.tiangolo.com/advanced/testing-dependencies/)：统一鉴权与外部服务边界的测试方式。
- [SQLAlchemy 2.x 事务](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html)：事务提交、回滚与会话边界。
- [Alembic 迁移](https://alembic.sqlalchemy.org/en/latest/tutorial.html)：版本化建表及升级管理。
