## 3. 多源输入方案

### 3.1 文档与文本

- 首页保留主题及长文本输入；文件入口接入 TXT 上传。
- PDF 使用 `pypdf` 提取文字和页码；支持全文或指定页码范围，保留引用页码。
- DOCX 使用 `python-docx` 按文档顺序提取段落和表格；TXT 处理常见 UTF-8、UTF-8 BOM、GB18030 编码。
- DOCX/TXT 没有可靠的固定分页，“指定页码”在原有控件位置禁用并解释原因，按全文解析；PDF 才启用页码输入。
- 后端验证实际文件内容、扩展名、大小、解压后体积和提取文字量。空文件、损坏文件、加密 PDF、扫描 PDF 和旧版 DOC 给出具体错误及替代操作。
- 大材料在提取成功后分段处理，再形成学习范围摘要；不静默截断成原先 5000 字的文本输入，不把前几页冒充全文。
- 文件在后端完成解析；上传临时文件及时清理。长期保留学习所需的提取文本、材料元信息和引用，原始二进制文件本期不永久保存。

### 3.2 网页

- 建议采用 Jina Reader API，接收公开 URL 并取得标题、正文、来源 URL。基础 Reader 可不配置密钥运行，实际服务限流、超时和失败必须处理；生产环境可配置专用密钥。
- 使用可替换的抓取适配器，前端不直接请求第三方服务。网页链接会发送给 Jina；上传文档不经 Jina 解析。
- 校验 HTTP/HTTPS 地址、目标主机及跳转；拒绝本机、内网、云元数据地址、携带账号密码的链接及其他不受支持协议。限制响应大小与超时。
- 登录墙、验证码、无正文及无法访问等情况进入 E03/E05 对应恢复流程，保留原链接，可重试、换链接或粘贴正文。

### 3.3 视频

- 建议首批平台为 B站和 YouTube，采用 `yt-dlp` 的元信息与字幕提取能力；只读取字幕或明确标注的可读正文。
- 使用中文字幕优先、英文字幕回退的规则；区分人工字幕、自动字幕和页面正文。
- 支持原型 L04 的起止时间，按字幕时间戳筛选片段，校验起点、终点和实际可读范围。
- 没有字幕、平台限制访问、片段无文字时明确提示，并提供原型已有的粘贴笔记入口。视频简介不冒充完整视频内容。
- 平台支持须用实际公开视频验证。平台调整、地区限制及部分字幕需登录可能影响结果，不承诺所有公开视频都可解析。

### 3.4 来源确认与出题

- 完整串联：L01 材料入口 → L02/L03/L04 → L05 解析 → L06 来源与范围确认 → L07 出题 → 现有闯关、结果和报告。
- L05 显示真实阶段与状态，支持取消；任务状态存 MySQL，刷新可以查询，进程中断后能识别失败并重试，不虚构进度倒计时。
- L06 展示真实标题、摘要、范围、知识点和材料预览；原型“查看原文与引用”采用 K05 的既有阅读布局，仅实现材料查看所需内容。
- 出题请求引用当前账号所属材料 ID 和确认范围。服务端读取材料，不信任客户端提交的正文、来源或用户 ID。
- 题库、逐题讲解、历史详情保存来源类型、文件名/URL、页码或字幕时间。引用 ID 必须来自本次有效材料，不能接受模型虚构来源。
- 原型中的“允许联网补充”建议接入 Jina Search + Reader，默认关闭。开启后只用学习主题构建检索，不发送整份文档作为搜索词，额外来源单独标明。
- Jina Search 需要 `JINA_API_KEY`；未配置时保留原控件并禁用、说明原因。用户主动开启后若检索失败，明确提示重试或选择仅材料出题，不静默冒充成功检索。
- 继续使用现有 DeepSeek 配置；LangChain 使用结构化 Schema、Prompt 模板与网关统一处理校验、超时、重试、调用次数。

## 4. 个人分析方案

### 4.1 R04 知识地图

- 从当前账号已完成学习的真实主题、知识点及答题表现生成主题 → 知识点的层级关联，不推断未经证实的先修关系。
- 沿用原型的中心主题、分支节点、筛选项、状态图例和下方列表。地图显示选中主题的代表节点；其余知识点通过原型已有列表布局查看。
- 筛选内容来自真实记录，替换 HTTP、数学等示例数据；知识点名称做基础规范化，同名合并，保留可追溯的题目和学习轮次。
- 节点可进入相应历史、错题或从该知识点继续学习；不会跳到固定 HTTP 示例。
- 建议掌握度基于每道唯一题的最近一次有效首次学习/错题复习结果。同题重复练习不增加样本量，重闯不刷统计；手动清空错题不改变历史答题事实。
- 建议至少 3 道不同题且正确率达到 80% 才显示“已掌握”；存在未巩固错误显示“待巩固”；其余显示“可继续探索”。明确这是基于答题样本的估计。
- 无记录使用现有空态组件；数据多、名称长时保留可读标签与列表入口，不重新设计地图页面。

### 4.2 R05 学习数据分析

- 新增服务端聚合接口，涵盖近 7 天、近 30 天、全部和报告所需自定义区间，避免依赖一次性加载全部历史。
- 总体正确率 = 有效答对题数 / 有效题数，不平均各轮百分比。
- 完成题数、主题数、学习时间、每日趋势和题型表现按已完成首次新学统计；重闯和复习单独作为巩固依据，不重复累计新学成果。
- 使用上海自然日过滤，UTC 保存时间；没有作答的日期正确率为空，不伪造成 0%。
- 按原型显示统计、趋势、题型表现和学习量；“生成报告”接入 R06。

### 4.3 R06/R07 周期深度复盘

- 支持最近 7 天、最近 30 天和自定义日期；按原型选择“学习主题与时间”“正确率趋势与题型表现”“薄弱知识和下阶段建议”。
- 服务端冻结一份真实数据快照，包含时间范围、主题、题型、知识点、错题及复习变化，并与前一等长区间比较。
- 数值、趋势方向与掌握状态由程序计算；AI 负责解释变化、归纳错误原因及制定可执行复习建议。输出关联知识点/记录 ID，校验引用与实际数据一致。
- 样本不足时明确说明，不生成“长期能力已提升”等无依据结论；没有前期记录时不用“比上周更懂”的固定结论。
- 报告输入只引用本人数据快照，不能接受客户端自报分数。没有有效学习记录时不调用模型，提供原型空态。
- 按用户、日期、内容选择、数据快照摘要与 Prompt 版本复用成功报告；新增作答后可以生成更新报告。
- 报告及生成状态存 MySQL，支持失败重试、取消后查询和重新登录查看；报告失败不影响历史、答案、错题、奖励。
- R07 按原型支持保存 TXT 文字报告。微信端使用本地文件与系统分享能力，H5 使用下载；用自动测试和微信环境分别验证。

## 5. 数据与接口安排

本期继续使用 MySQL、SQLAlchemy 和 Alembic；不引入向量库。新增数据与旧账号、关卡关联，保留外键删除和用户隔离。

| 数据 | 用途 |
| --- | --- |
| 材料与引用 | 所属用户、来源类型、文件名/URL、提取文字、页码/时间、摘要、范围、内容摘要值 |
| 解析任务 | 幂等标识、真实阶段、完成/失败/取消状态、结果、超时与重试信息 |
| 周期报告 | 日期及内容选择、数据快照、生成状态、报告 JSON、生成次数、版本 |
| 关卡来源元信息 | 原有关卡 JSON 增加可选来源字段，旧关卡默认文字输入 |

知识地图和学习分析首先从可信学习记录聚合，避免维护一套会与答题历史脱节的重复统计。必要索引由实际查询计划确定。

接口分组包括：上传解析、链接解析、视频解析、任务查询/取消、材料查看、知识地图、学习分析、周期报告生成/查询/导出。沿用现有统一响应、Bearer 鉴权与幂等规则，并补充材料不支持、范围无效、无可读内容、上游限流等明确错误。

现有 `quiz/generate` 增加材料来源选项，保持原文字请求可用；旧历史和已有报告继续可读。正式实现前以 Pydantic 和 OpenAPI 固化字段及校验规则。

## 6. 建议默认限制（待确认，均可配置）

| 项目 | 建议默认值 |
| --- | --- |
| 上传文件 | 单份 20 MB |
| PDF | 最多解析 200 页；超出时选择不超过上限的页码范围 |
| 提取正文 | 单次最多 10 万字符；超出时明确要求缩小范围，不静默截断 |
| 新材料解析 | 每账号每日最多 20 次实际开始的解析操作；重复请求复用结果，格式校验失败不计数 |
| 周期报告 | 每账号每日最多 5 次实际开始的生成操作；成功缓存命中不计数 |
| 同一报告快照 | 首次加最多 2 次手动重试；成功后复用 |
| 自定义报告区间 | 最长 366 天，不接受未来日期或开始晚于结束 |
| AI 并发与分钟限流 | 继续每账号同时 1 个 AI 操作、每滚动 60 秒 3 次实际模型调用，覆盖解析摘要、出题和两类报告及内部重试 |
| 新关卡额度 | 继续每日 10 次；解析材料不额外消耗新关卡次数，真正出题才按现有规则扣减 |

文件、页数、文字量限制是处理上限，不是收费套餐。解析和报告新增计数存 MySQL；取消或失败前已经发起的实际服务调用计数不返还。临时、未被关卡引用的材料建议 24 小时后清理，已引用材料随学习记录保存，注销一并删除。

## 8. 确认后执行的开发步骤

1. **建立基线。** 核对工作区、现有前后端测试和构建；确认 MySQL 业务库/专用测试库隔离。记录既有失败，先处理阻碍本任务的环境问题，保留其他工作。
2. **材料数据及解析任务 TDD。** 先写鉴权、用户隔离、幂等、迁移、任务阶段、取消及失败恢复测试，再实现模型、迁移和任务服务。
3. **文档、网页、视频解析 TDD。** 先用真实 PDF/DOCX/TXT 测试文件和可控上游响应验证提取、范围、错误、大小与 URL 校验，再接入解析器、Jina 与字幕适配器；完成真实公开来源的烟雾验证。
4. **材料出题与引用 TDD。** 先验证材料归属、范围、来源约束、联网开关、模型结构校验、限额和重试，再实现摘要/出题链及现有闯关链路衔接。
5. **知识地图和分析 TDD。** 先验证跨历史聚合、题数加权、题型、上海日期、去重、复习影响和样本不足规则，再实现服务端接口和历史兼容。
6. **周期报告 TDD。** 先验证范围、内容选择、可信快照、前期比较、缓存、并发、重试、额度、无数据、导出与隔离，再实现报告链和持久化。
7. **原型前端 TDD。** 逐条先写接口/状态单元测试和端到端失败用例，再实现 L02–L06、R04–R07 和关联入口；分别适配微信文件选择上传与 H5 文件选择，保持原型布局。
8. **回归与交付。** 跑完整后端和前端测试、类型检查、H5 与微信构建、样式和启动检查；对照 320/390px 原型截图并验证真实来源。更新配置、迁移、运行说明和验收证据，报告真实微信验证范围。

每个功能切片都执行“新增测试失败（RED）→ 最小实现通过（GREEN）→ 重构及回归”，保存可复核结果；不会等实现完成后再补测试。

## 9. 验收标准

- 文字、TXT、文字 PDF、DOCX、公开网页及有公开字幕的视频均能从首页进入真实材料解析、范围确认、出题、答题、报告闭环。
- PDF 页码、视频片段确实影响学习内容；失败保留输入，重试不重复创建同一材料或重复扣减同一幂等操作。
- 知识地图和周期报告因不同账号、主题、作答、复习及时间范围而变化；不存在固定 HTTP 示例或虚构的统计数值。
- 报告成功复用、失败可恢复、跨账号不可读；新增功能不破坏原有奖励、锁定首答、历史、错题和注销规则。
- 数据库测试使用现有专用 MySQL 测试库；文件解析使用真实格式的文件。外部服务替身仅用于控制网络成功、失败和超时，不替代业务和持久化验证。
- 前端自动化覆盖正常与异常流程；完成 TypeScript、单元测试、H5/微信构建和原型对照。真实微信文件选择、上传、文件分享及权限需要在微信环境单独验收，不能以 H5 通过替代。
- 交付完整源代码、版本化迁移、配置样例、测试结果、原型对照截图和验收记录。外部平台受限或本地配置缺失时，如实说明具体未完成的真实联调项目。

## 10. 已查询的最新技术依据

已通过 Context7 查询 Taro、LangChain 和 FastAPI 官方文档，编码时继续按本项目实际安装版本核对具体接口，不为“最新”盲目升级整个项目。

- [Taro chooseMessageFile](https://docs.taro.zone/docs/apis/media/image/chooseMessageFile)：微信选择文件返回临时路径；该接口不支持 H5，需要跨端分支。
- [Taro uploadFile](https://docs.taro.zone/docs/apis/network/upload/uploadFile)及 [UploadTask](https://docs.taro.zone/docs/apis/network/upload/UploadTask)：上传返回字符串响应，支持进度和中止，鉴权头随请求传递。
- [LangChain models / structured output](https://docs.langchain.com/oss/python/langchain/models)：Pydantic 输出校验、`include_raw`、不同结构化输出模式及兼容服务 `base_url`；继续使用已验证的 JSON mode，并在 Prompt 描述 Schema。
- [FastAPI 文件上传](https://fastapi.tiangolo.com/tutorial/request-files/)及 [UploadFile](https://fastapi.tiangolo.com/reference/uploadfile/)：multipart 上传、分块读取和文件资源关闭。
