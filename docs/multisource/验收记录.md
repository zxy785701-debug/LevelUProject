## 升级与配置

继续采用 Python/FastAPI、MySQL、Taro 4.3.0、React 18 和 LangChain。本轮新增并锁定 pypdf 6.20.0、python-docx 1.2.0、yt-dlp 2026.8.19 及 lxml 6.1.3；没有升级整个现有技术栈。

1. 在后端环境安装 `backend/requirements.lock`。
2. 保留现有后端 `.env`，参照 `.env.example` 补充可选 Jina 密钥及材料限制。密钥不进入前端或构建包。
3. 使用原有 `scripts/start-backend.ps1`，自动执行新增迁移 `003_materials_analytics`。迁移增加三张表、解析/报告额度和统计索引，保留既有数据；升级前按现有部署流程备份。
4. 微信开发者工具导入 `frontend/`，重新构建后普通编译；真机使用 HTTPS API 并配置 request/uploadFile/downloadFile 合法域名。
5. 按 [README](../../README.md) 启动或执行自动化验证。测试服务只绑定本机 8001；正式 API 不包含测试登录入口。

默认限制：20 MB、200 页 PDF、10 万字符，每天 20 次解析、5 次周期报告；自定义报告最长 366 天。所有实际模型调用，包括内部重试，继续共用每账号一分钟三次及单个并发限制。同一报告最多三次发起，成功结果直接复用。

解析任务和材料按账号隔离。未被引用材料与解析任务 24 小时后清理；已引用材料随学习记录保留，注销级联删除。解析中断会成为可恢复失败，不伪装成功或无限显示进度。

## 8000 端口接口 404 修复

用户反馈微信中知识地图与数据分析返回 404 后，检查发现：源码已注册接口，但 8000 端口仍运行未加载新增路由的旧后端。该服务的实际 OpenAPI 清单缺少 `/api/v1/knowledge-map` 和 `/api/v1/analytics`，失败证据见 [本机接口 RED](../../backend/test-results/multisource/17-local-api-red.json)。

已确认进程属于本项目后重启，执行数据库迁移并加载新代码。同时修改 `scripts/start-backend.ps1`，在本地开发中使用 `--reload --reload-dir app`；修复原脚本在 Windows PowerShell 5.1 读取无 BOM 中文错误消息时的语法兼容问题。启动脚本现已实际运行通过，后端保持运行。

在真实 8000 服务创建本次验证专用的临时账号，先检查空态，再用该账号的合成三题记录提交两对一错的答案：知识地图返回 200，显示三题、两题正确及待巩固状态；分析的 7/30/all/custom 四种范围均返回 200，统计三题、两题正确、67% 正确率。结果见 [本机接口 GREEN](../../backend/test-results/multisource/18-local-api-green.json)。临时账号及其学习记录已删除，未修改真实用户的学习数据，也未消耗模型调用额度。
