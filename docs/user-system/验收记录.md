# 用户系统扩展验收记录

日期：2026-10-12。范围依据：[已批准方案](../用户系统扩展方案.md)。仅扩展 `frontend/` 与 `backend/`；`frontend-comic/` 的已有变更不属于本次工作。

## 实现结果

- 未登录强制进入 A02 登录页；微信 code 由后端交换身份，首次登录自动建号，业务凭证保存摘要并在 7 天后失效。退出撤销当前会话；所有业务接口统一鉴权。
- A01 原位置接入主动选择头像、填写昵称和默认资料。头像校验实际图片并转换保存，昵称通过微信原生表单提交；不依赖已废弃的自动读取资料行为。
- MySQL 保存关卡、首次答案、暂停进度、完成记录、错题、报告、金币及 XP。服务端判分，首答锁定；答案、奖励和余额在同一事务更新。未作答题目的正确答案和讲解不提前下发。
- 新学首次答对 +10 XP/+2 金币；重闯与错题复习不重复奖励。个人中心与分析使用当前账号的真实数据，完成的新学记录按题数加权计算正确率，连续学习按上海日期计算。
- 出题每日 10 次、每滚动 60 秒最多 3 次实际模型调用、出题与报告共享 1 个并发名额；包含网关内部重试。计数与操作状态持久化，客户端取消或模型调用失败不退还已使用额度。
- 出题结果和成功操作状态原子提交，过期结果禁止入库；同一幂等键复用结果，参数冲突拒绝执行。报告只接收本人已完成记录 ID，成功后复用，最多首次加 2 次手动重试。
- 云端历史、错题状态、清空待复习队列、导出、清理账号缓存及账号注销接入现有页面。注销须二次确认和当前微信重新验证；删除个人与学习数据，当期防刷摘要到周期结束后清理。
- 账号缓存隔离；过期凭证回登录；迟到响应不能覆盖另一个账号。旧游客本机数据不自动导入账号或兑换奖励。
- `GET /api/v1/attempts` 提供分页、完成状态、学习模式和 7/30 日筛选；现有前端历史和分析基于当前账号同步快照筛选。

## 真实微信人工验收

本机开发者工具版本 2.01.2510290、基础库 3.17.4。

1. 初次报告 `TypeError: n[e] is not a function`。核对当前完整构建的依赖与 App/页面加载均通过，重新构建并通过官方 CLI 清除该项目的**编译缓存**，随后人工普通编译确认进入登录页。未清除登录存储或业务数据。
2. 人工确认真实微信登录成功，进入首页和“我的”；后端真实 `/auth/wechat`、云端记录请求返回成功。
3. 人工确认主动选择头像、保存昵称，退出登录再登录后两项均恢复成功。业务库只读检查也确认头像及自定义昵称已保存，不输出资料具体值。

微信工具 CLI 的自动打开/自动化仍报工具内部 `d.on is not a function`，因此以上原生能力采用人工验收，未宣称自动化接管成功。该问题不影响已完成的手动编译、登录和资料验证。真机相册、分享、正式 HTTPS 域名和上线配置仍需要部署环境验证。

## 运行与复测

正式后端使用 `scripts/start-backend.ps1`，自动迁移后监听 8000；微信工具打开 `frontend/`。业务账号及已保存资料保留。

```powershell
# 后端、前端单元测试及类型检查；只重置 levelup_test
./scripts/check.ps1

# 单独终端：专用测试服务，8001
cd backend
.venv/Scripts/python.exe -m tests.serve_accounts_e2e

# 另一个终端：构建和浏览器回归，H5 预览需监听 10086
cd frontend
npm run build:h5
npm run test:e2e
npm run build:weapp
npm run check:startup

# 可选真实 AI 验证，会产生模型费用；测试库流程使用进程内微信适配器
cd ../backend
.venv/Scripts/python.exe scripts/live_accounts_eval.py
```

不要让清理测试库的单元测试与端到端/真实 AI 测试同时运行。H5 没有正式微信登录入口，也没有在业务后端添加免微信登录的接口。

## 追加交互与奖励验收（2026-10-12）

已人工确认采用 A 方案：任意题号可点选，上一题／下一题可切换未作答题；首次提交锁定答案，全部题目作答后方可结算。未提交的多选草稿在切题时保留，未答题仍不向客户端发送答案或讲解。

进阶新关卡每题首次答对为 15 XP＋3 金币，入门为 10 XP＋2 金币。服务端生成关卡时保存奖励规则快照，奖励账本、个人余额、报告、导出和前端统计使用同一规则。旧关卡没有快照时继续按 10 XP＋2 金币计算，不追溯修改已发奖励。乱序复习按题目对应原始错题更新状态，重闯和复习不发奖励。数据保存在既有 MySQL JSON 字段内，无需修改历史数据或增加数据库表。

头像改为操作菜单，提供预览、保存图片和原生更换入口；处理相册权限拒绝后的设置入口。首页金币增加文字标识，生成按钮使用原有星星的白色版本。各页面按页面及记录保存滚动位置，返回时恢复。HTML 原型与全部 9 个入口同步更新。

后端按 TDD 先运行新增测试（3 失败、1 通过），实现后 4 项新增场景通过，全量 111 项通过，总覆盖率 93%。前端 18 项测试及 7 项端到端测试通过（含原生相册保存成功、拒绝权限、打开设置和取消分支），覆盖乱序答题、草稿、锁定、完整结算、15／3 奖励、头像预览及 JPEG 实际下载、320px 布局与滚动恢复。原型 69 页无运行错误，乱序完成三题得到 45 XP＋9 金币，头像选择、预览、下载及返回滚动位置均通过。
