# LevelUProject · 第二轮设计规范

状态：草图审阅，待人工确认。参考文件作为完整性检查来源，以下内容为本项目独立方案。

## 1. 品牌与布局

产品名严格使用 **LevelUProject**。主导航为闯关、复盘、我的。答题页集中呈现本轮进度和题目，报告页集中呈现学习收获。核心操作尽量一步可达。

展示目录、独立设计规范页、六组业务画廊分别制作 HTML。宽屏每行三列，中屏两列，窄屏一列；正式开发时以手机稿 390px 和可读字级决定断点，不能缩小文字来硬塞三列。

## 2. 色彩与语义

| 色彩 | 值 | 用途 |
| --- | --- | --- |
| 纸白 | #FFFFFF | 题面、长文、主要阅读面 |
| 墨黑 | #26211F | 文字、重要边框、实体投影 |
| 课本黄 | #FFD84D | 主行动、当前节点、奖励提示 |
| 圆珠笔蓝 | #4D8FFF | 已选、链接、章节划线、角色主色 |
| 过关绿 | #68BA88 | 正确、成功、完成 |
| 订正红 | #EB7465 | 错误、薄弱点、需要处理的状态 |

每屏最多一处大色块焦点。题面以白为主，蓝黄作为品牌识别，绿红仅传达语义。任何正确/错误状态同时使用文字与形状标识。角色插画允许少量手绘明暗，界面组件使用平涂与清楚的边界。

## 3. 字体与阅读

草图使用微软雅黑常规与粗体。正式 HTML 的中文主体使用本地系统黑体回退链，标题通过字重和手绘章节标记表现漫画感，不依赖必须联网下载的字体。

| 内容 | 字级 | 行高 |
| --- | --- | --- |
| 页面主标题 | 24–28px | 1.3 |
| 题干 | 20–22px | 1.5 |
| 区块标题 | 18–20px | 1.4 |
| 正文与选项 | 16px | 1.6 |
| 辅助信息 | 12–14px | 1.5 |

数字采用等宽数值排版。题干和正文避免孤立标点；长题自然换行，不压缩字级。标题装饰只出现在短标题附近，不压在讲解正文上。

## 4. 形状与层级

- 一般边框约 2px，主按钮与主漫画格约 2.5–3px，浅分隔使用细实线或短虚线。
- 小标签圆角约 8px，按钮约 12px，主漫画格约 16px；手机外壳仅用于原型审阅。
- 普通阅读组不强加外框；需要操作的分组有轻边框；主要动作采用约 4px 的硬投影。
- 每屏只强调一个主要动作。数据分析与设置页减少粗边框，通关与分享页可增强漫画分格。

## 5. 按钮与输入状态

| 控件 | 必须展示的状态 | 行为 |
| --- | --- | --- |
| 主要按钮 | 默认、按下、加载、禁用、键盘焦点 | 课本黄为主；按下时短暂下沉；加载阻止重复触发；禁用保留名称 |
| 次要按钮 | 默认、按下、焦点 | 白底墨字，层级低于主按钮 |
| 文本输入 | 空白、已输入、聚焦、过长、错误 | 保留用户内容；错误显示具体调整方向；不强制每次修改都弹窗 |
| 文件与链接 | 未选择、已选择、处理中、成功、失败 | 可替换、取消、查看来源、重试 |
| 开关 | 开启、关闭、不可用、焦点 | 名称与状态均可读，不只依赖颜色 |

主题为空时“开始生成关卡”禁用，提供可点击示例。题量与难度默认折叠，文档和链接解析后再确认学习范围。

## 6. 答题组件

选项具有未选、已选、正确、错误四态。未选白底，已选浅蓝，正确浅绿并带正确标记，错误浅红并带错误标记。

单选和判断选择后即时判题；多选勾选后显式提交。题型说明明确是否可以多选，具体是否提示正确项数量待人工确认。提交后锁定本题，答错时同时展示所选错误项与正确项。

知识讲解先显示结论和关键原因，详情可展开；保留来源入口。反馈进入阅读状态，不以动画自动跳过讲解。即使答错也能继续本轮。

## 7. 漫画语汇

独立使用三类表达：圆珠笔式章节划线、局部折角书签、与角色对应的对白框。对白框尾部指向发言者；知识正文不用密集网点底纹。红笔用于订正与薄弱点提示，蓝线用于学习组织。

贴纸用于连击、通关、成就，限于少量短语。普通设置、文件列表和统计图不滥用拟声词或倾斜文本。主界面不复用参考中的全页网点、三色大描边字与阿皮角色结构。

## 8. 游戏数据与分析

本轮进度、累计 XP、金币余额分别标明，不能混淆。演示规则暂定单题答对 +10 XP、+2 金币；错误不扣已有 XP；连击额外奖励待确认。

正确率按实际作答统计，知识点掌握程度标注为估计。趋势图有时间轴和单位；样本不足时给出可理解的提示。单轮 4/5 正确对应 80%，奖励为 40 XP、8 金币。连续答对三题对应基础 30 XP。

不在单人报告中展示没有统计依据的超过人群百分比。收费是否触发需与文件大小、配额和演示规则一致。

## 9. 吉祥物与出场

| 候选 | 核心概念 | 定位 |
| --- | --- | --- |
| A · U 形书灵 | 名字中的 U 变成一本活起来的书 | 推荐，品牌关联最直接 |
| B · 涂鸦铅笔同学 | 写下一个问题，开始一次学习 | 校园感与动作扩展更强 |
| C · 纸团探险家 | 把试错变成下一步灵感 | 故事感与探索意味更强 |

三者均为本轮新生成的原创候选，透明原图位于 `mascots/`。UI 草图暂用 A；选择身份后再统一制作欢迎、思考、答对、订正、通关等表情与动作，避免现在混用不同角色。

角色主要出现在欢迎、等待、反馈、结算与分享。长题和数据页降低角色占比；不能为了插画挤压题干、讲解或主要按钮。

## 10. 动效与可访问性

操作按下约 100–140ms，选项状态切换约 180–220ms，奖励出现约 300–420ms，通关强调约 700–900ms。动效仅响应操作，不持续漂浮或循环闪动。

支持减少动态效果、可见键盘焦点、清楚的加载状态与足够点击区域。移动端控件提供约 44px 的有效点击区域。任何长文本、弹层和按钮都不能溢出手机安全区。

## 11. 异常、权限与恢复

每次 AI 获取、解析、出题和报告生成都有对应的加载、成功、失败和取消状态。失败保留输入与已获得的数据，给出一个明确主恢复动作。

报告失败时保留基础统计；断网恢复不重复发放奖励；权限拒绝提供可行替代入口。清空记录与注销使用具体内容的确认变体，原型只演示流程，不真实删除数据。

以上规范及 69 项清单待本轮人工确认后落实到完整 HTML。
