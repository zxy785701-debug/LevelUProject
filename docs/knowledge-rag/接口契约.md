# 个人知识库接口契约

统一前缀 `/api/v1/knowledge`；沿用 Bearer 鉴权和 `{code,message,data}` 成功 envelope。跨账号资料和片段按 404 返回，不区分不存在与他人数据。客户端不能指定用户、索引集合、文件路径或任意过滤表达式。

## 已实现的读取

- GET `/capabilities`：enabled、available、embedding_available、web_available、reason_code、worker 的真实心跳状态、支持格式、限制及云端处理说明。无凭据和目录信息。检查不创建文件/向量客户端，不调用收费服务。
- GET `/documents?page=1&page_size=20`：items、total、page、page_size；page 为 1–10000，page_size 为 1–100。条目包括 id、title、source_type、status、受控 source 元信息、active_revision_id、version、text_chars、chunk_count、job_id、安全错误和时间。
- GET `/documents/{id}`：相同资料 DTO。无内部文件路径、向量、私有任务载荷。
- GET `/documents/{id}/chunks`：仅活动且完整发布的版本；返回分块 id、revision_id、position、原始 text、真实 location 和分页。暂存版本不可见。

选中范围必须为明确的本人资料 ID 列表，或 all_ready=true 且不混用列表；空列表不代表全部。所选资料必须就绪，活动版本和 Embedding 配置须一致；确认/发布前重新核验版本和删除状态。

## 导入提交

- POST `/documents/upload`：multipart 的 file，支持 PDF/DOCX/MD/Markdown/TXT，实际接收上限 20 MB；原始文件保存到服务器生成的私有路径，重处理不在请求中执行。
- POST `/documents/web`：`{url}`，只接受公开 HTTP(S) 地址，后台取得实际正文后才能就绪。
- POST `/documents/from-material`：`{material_id}`，只复制本人的可用文档/网页正文，独立于原临时记录清理；不把视频或模型摘要当作知识库正文。

导入使用 Idempotency-Key；相同账号/类型/键和参数复用原任务，参数变化返回 409。返回 `kind=knowledge_job`，id/job_id 为任务 ID，document_id 为资料 ID，job_type、status、stage、progress、deadline、error_code/message 和 result 均有明确含义。queued 不代表解析或入库成功，也不代表最终 Session。

## 前端恢复与管理

- GET `/materials`：分页列出本人可复制的 PDF/DOCX/TXT/网页材料摘要（id/title/source_type/created_at），不返回正文或内部路径，不列视频。
- GET `/job-lookup?job_type=...&key=...`：按当前账号、任务类型和原幂等键找回已持久提交；响应丢失时先查原提交，避免重新上传或重复扣费。关闭新入口仍可查询。
- DELETE `/documents/{id}`：返回 deleted=true 及真实持久 cleanup 标识；重复删除返回同一清理身份。GET `/cleanup/{id}` 查询本人的清理状态，不暴露清理载荷，也不允许取消必要清理。

`27-frontend-contract-red.xml` → `27-frontend-contract-green.xml`：14 passed，包含资料管理和清理回归。清理状态 kind=knowledge_cleanup，与普通 knowledge_job、答题 Session 明确区分。
