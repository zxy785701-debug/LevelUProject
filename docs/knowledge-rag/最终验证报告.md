## TDD 与关键路径

逐切片 RED/GREEN 原始 TXT、JUnit XML 和命令保存在本目录，初始失败记录不删除。领域说明记录对应编号：配置与隔离 01–02；数据库/账号/API/导入 03–06；持久任务、锁与预算 07–11；解析分块 12–13；向量/索引/清理 14–16；来源/Agent/预算/提示注入 17–19；问答/审核/历史 20–22；范围/出题/原子发布与旧学习流程 23–26；启动兼容 27–28；追加边界与真实联调缺陷 33、40、43、46–47。

审查与测试覆盖的关键路径：

| 路径 | 核验 |
|---|---|
| 跨账号读取、检索、任务、发布 | 每次 SQL 权属/活动版本复核；不可由客户端覆盖路径或范围 |
| 崩溃、租约接管、取消竞态 | fencing、固定期限、唯一发布；旧执行者与迟到结果不可提交 |
| 原子关卡发布和奖励 | Session / 操作结果 / 任务在同事务；恢复不重复扣资格或发奖励 |
| 索引完整性 | 全量向量校验后切版本；半成品不可见；损坏/缺失明确技术失败 |
| 注入与资料外发 | 文件正文按不可信内容处理；公网工具只接收服务端允许的公开参数 |
| 模型预算 | 实际请求、独立审核和失败重试计数；恢复不清空预算 |
| 依据不足/冲突 | 无证据不编造；冲突按来源说明；审核失败最多一次修正 |
| 历史与删除 | 立即停止检索，后台 outbox；注销后清理仍存活；必要快照不丢失 |
| 可选能力关闭 | 核心健康、旧功能继续运行；清理不被开关丢弃 |
| 前端恢复 | 同幂等键恢复，单调进度，切账号丢弃迟到结果，切后台暂停轮询 |

## 人工验收状态

用户目前只能使用本机微信开发者工具，未具备手机可访问的 HTTPS 后端，因此微信真机验收未完成。

2026-10-19 用户实际反馈：点击「选择文件」没有打开选择窗口，随后页面出现统一失败提示。工具版本 Windows mp 2.01.2510290、基础库 3.17.4。在 Console 中直接调用 `wx.chooseMessageFile`（带或不带 extension）均返回 `The "fd" argument must be of type number. Received undefined`，证明原生文件窗口在该工具环境内失败，尚未进入上传请求。

本地 Taro 4.3 运行时对该 API 直接委托 wx，因此应用增加回调式成功/失败适配，同时观察可能返回的 Promise，避免 undefined 被误当作结果及悬空拒绝。对已观察到的 fd 异常提供重启/更新开发者工具的明确提示，继续隐藏本地路径。`64-picker-red-valid` 两项失败 → `64-picker-green-unit` 全部 54 项通过。该兼容修复不等于已修复工具内部错误，仍需用户完全退出并重启工具后实际复测，H5 自动化不能替代。

2026-10-19 后续用户实际复测确认：「重启后可以打开文件窗口」。文件窗口恢复已通过人工确认；上传建库及其他微信操作尚不能由此推定通过。

OpenSpec 任务 10.3 保持未完成，不归档变更。

## 复现命令

在 backend 执行（需本机隔离测试库权限）：

```powershell
.venv/Scripts/python.exe -m pytest -q --cov=app --cov-config=tests/knowledge.coveragerc --cov-report=xml:../docs/knowledge-rag/final-new-coverage.xml --junitxml=../docs/knowledge-rag/final-new-tests.xml
```

在 frontend 执行：

```powershell
npm run typecheck
npm test
npm run build:h5
npm run build:weapp
npm run check:wxss
npm run check:startup
npm run check:assets
```
