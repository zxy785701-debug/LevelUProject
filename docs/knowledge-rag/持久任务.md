# 持久任务状态与执行器

## 状态及客户端契约

`queued → running → succeeded / failed / cancelled`。租约过期的 running 可以由新执行器接管；可恢复失败最多累计执行 3 次。成功才允许 progress=100，其他状态保留已有进度，人工重试同样不能倒退。

- GET `/api/v1/knowledge/jobs/{job_id}` 查询；原账号资料权属检查适用于每次控制和发布。
- POST `.../{job_id}/cancel` 取消排队或运行中的任务；重复取消保持同一终态，已成功的结果不反转。
- POST `.../{job_id}/retry` 配合新的 Idempotency-Key 返回恢复任务；相同键复用，其他键也不会并行恢复同一操作。不能延长原始截止时间、清零累计调用预算或绕过次数上限。

例如上传返回 `{kind:"knowledge_job",job_type:"import",status:"queued",progress:0,...}`。轮询后可能变为 `{status:"running",stage:"embedding",progress:70,...}`。取消会返回 cancelled/70；迟到的处理结果不能发布。重试在原期限内返回 queued/70，并沿用根 operation_id 的检查点和预算。此 DTO 不是答题 Session。

关闭新入口仍允许查询和取消已提交任务；重新执行要求配置可用。查询及错误只返回稳定错误码和安全说明，不含正文、密钥或本地路径。已注销账号无法查询、重试或提交旧结果。

## 存储边界

MySQL `FOR UPDATE SKIP LOCKED` 原子领取；owner、递增 fence、lease_until、deadline_at 每次写入前核验。租约接管不重置 attempts、budget 或 deadline。排队最长 600 秒，导入 900 秒、问答 180 秒、范围准备 240 秒、出题 300 秒，均为首次提交后固定期限。

结果回调、根操作唯一结果和任务 succeeded/100 位于一个数据库事务。回调失败全部回滚；同一完成调用重发只读已发布结果。文档删除和账号注销会阻断迟到发布。

## 单执行器边界

执行器先持有专用目录的操作系统文件锁，再取得 MySQL 执行器租约；二者缺一不可。锁一直保留到同步处理线程停止，数据库心跳由独立异步循环续租。最多两个处理线程；清理 outbox 在新导入前取得执行机会，交互任务按优先级领取。关闭新功能入口不会自动丢弃持久清理或已有任务。

`09-worker-red-valid.xml` → `09-worker-green-final.xml`：19 passed。真正启动第二个进程验证目录锁拒绝，持锁进程退出后可重新取得；数据库租约接管后旧执行者不能续租；两个耗时线程同时工作时心跳继续更新，第三个任务等待，交互优先；异常说明不包含原始错误内容。

MySQL 现有 DATETIME 精度为秒，因此心跳验证跨过一秒观察窗口，首次 0.2 秒断言的失败记录仍保留。真实服务调用、AI 额度衔接、索引流水线与执行器启动手册在对应任务完成后补充。

## 额度与运行入口

语言模型每次实际发出前，在任务租约事务内调用旧账号计量适配；共享滚动 60 秒 10 次及单账号执行资格。排队不预占忙碌资格。问答首次模型调用扣独立问答次数，范围准备沿用准备次数，闯关首次实际调用才扣旧出题额度；恢复保留原 ai_operation_id 和 charged。取消、失败和完成在本事务释放资格。等待额度有原始截止时间，并显示 waiting_ai / retry_after_seconds。

Embedding 每次请求独立预留当天 Token；收到可信用量后回填，重复回填幂等。取消后的付费响应仍可计量，但不能发布内容。丢失响应的预留保留，重启不退款；不消费模型分钟调用或闯关次数。

`10-budgets-red.xml` → `10-budgets-green.xml`：19 passed（包含任务/执行器）。`10-budgets-regression.xml`：70 passed，覆盖旧账号、旧模型预算及共享事务适配。

- `scripts/start.ps1` 在旧迁移/后端启动流程后检查可选执行器，有可用心跳时复用；只记录本次启动的进程并在退出时停止它们。
- `scripts/start-knowledge.ps1 -Check` 只检查配置；`-Status` 读取数据库心跳；无参数启动独立执行器。先按原方式执行迁移，执行器不会自行改业务库结构。
- 独立等价入口：在 backend 执行 `.venv/Scripts/python.exe -m app.knowledge.worker`。输出仅记录任务 ID、类型、稳定错误码及启动停止状态，启动器日志在 backend/logs/start-knowledge.*.log。
- 新功能关闭且没有专用存储时不启动；已有专用存储仍启动以处理持久任务与清理。停止前保留目录锁直到线程退出；异常进程退出由租约超时接管。后续处理器接入在对应流水线任务验证。

`11-launcher-red.xml` → `11-launcher-green.xml`：3 passed；启用/关闭配置均在独立 Python 进程启动停止，仅读测试库与临时目录；真实 PowerShell helper 启动两个无害进程，确认停止自身进程后另一个仍存活，再清理本测试自身的另一进程。既有进程退出码脚本继续保留。

发现早期未采用提权测试通道的空日志基线进程仍挂起；核对其完整命令与父子 PID 后仅停止了本任务的两级 Python 进程。有效基线为实施基线文档的 391 passed 报告，不使用空日志作为证据。
